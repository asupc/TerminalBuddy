# TerminalBuddy 配置效率指南

## 为什么使用配置？

配置让你**一键启动**常用工作环境，告别重复操作：

- 每次打开项目都要 `cd` 到目录？ → 配置启动目录自动进入
- 每次启动都要输入相同的命令？ → 配置启动命令自动执行
- 频繁连接远程服务器？ → 配置 SSH/MSTSC 一键连接
- 多个项目来回切换？ → 用分组管理，快速定位

---

## 如何创建配置

### 1. 打开配置编辑器

点击左侧配置面板的 **"+"** 按钮，选择终端类型。

### 2. 填写基本信息

| 字段 | 说明 |
|------|------|
| **名称** | 显示在界面上的名称，如 `"前端开发"` |
| **分组** | 使用 `/` 创建层级，如 `"项目A/开发"` |
| **终端类型** | PowerShell、CMD、SSH、Docker、K8S、远程桌面 |

### 3. 配置启动行为

| 字段 | 说明 |
|------|------|
| **启动目录** | 打开终端后自动进入的目录 |
| **启动命令** | 打开终端后自动执行的命令（每行一个） |

## 常见场景配置

### 场景一：项目开发终端

**需求**：每次打开终端自动进入项目目录并启动开发服务器

**配置步骤**：
1. 名称：`前端开发`
2. 分组：`我的项目`
3. 终端类型：`PowerShell`
4. 启动目录：`D:\projects\my-app`
5. 启动命令：
   ```
   npm run dev
   ```

**效果**：点击配置 → 自动进入目录 → 自动启动开发服务器

---

### 场景二：多 Node.js 版本切换

**需求**：不同项目需要不同的 Node.js 版本

**配置步骤**：

为每个项目创建专用配置，启动命令中切换版本：

| 配置名称 | 启动命令 |
|----------|----------|
| 旧项目 (Node 16) | `nvm use 16.20.2`<br>`npm run dev` |
| 新项目 (Node 18) | `nvm use 18.19.0`<br>`npm run dev` |
| 最新项目 (Node 20) | `nvm use 20.10.0`<br>`npm run dev` |

支持的版本管理器：nvm-windows、nvs、fnm

**nvs 示例**：
```
nvs link 24.15.0
npm run dev
```

---

### 场景三：批量操作

**需求**：一键拉取所有项目代码

**配置步骤**：
1. 名称：`批量 Git Pull`
2. 分组：`运维`
3. 启动命令：
   ```
   cd D:\project-a && git pull
   cd D:\project-b && git pull
   cd D:\project-c && git pull
   ```

**效果**：一键执行，无需逐个切换目录

---

### 场景四：SSH 快速连接

**需求**：频繁连接远程服务器，不想每次都输入地址和密码

**配置步骤**：
1. 终端类型：`SSH`
2. 填写服务器信息：

| 字段 | 说明 |
|------|------|
| **主机地址** | IP 或域名，如 `192.168.1.100` |
| **端口** | 默认 22 |
| **用户名** | 登录用户名 |
| **认证方式** | 密码 或 密钥 |
| **密码/密钥路径** | 根据认证方式填写 |

**效果**：点击即连，无需每次输入

---

### 场景五：远程桌面

**需求**：快速连接 Windows 远程桌面

**配置步骤**：
1. 终端类型：`远程桌面 (MSTSC)`
2. 填写连接信息：

| 字段 | 说明 |
|------|------|
| **主机地址** | 远程桌面服务器地址 |
| **端口** | 默认 3389 |
| **用户名** | 登录用户名 |
| **密码** | 登录密码（加密存储） |
| **分辨率** | 如 `1920x1080` |

**效果**：比系统自带远程桌面更快，支持凭据保存

---

### 场景六：全栈开发

**需求**：前后端同时开发，需要两个终端

**配置步骤**：

创建两个配置：

| 配置 | 启动目录 | 启动命令 |
|------|----------|----------|
| 后端服务 | `D:\project\backend` | `npm run start:dev` |
| 前端服务 | `D:\project\frontend` | `npm run dev` |

**效果**：打开两个配置，前后端同时开发

---

### 场景七：环境初始化

**需求**：新电脑需要初始化开发环境

**配置步骤**：
1. 名称：`环境初始化`
2. 启动命令：
   ```
   nvm install 18
   nvm use 18
   npm config set registry https://registry.npmmirror.com
   npm install -g yarn pnpm
   ```

**效果**：一键配置好开发环境

---

### 场景八：Python 多版本

**需求**：不同项目使用不同 Python 版本

**配置步骤**：

| 配置名称 | 启动命令 |
|----------|----------|
| Python 3.9 项目 | `py -3.9 -m venv .venv`<br>`.venv\Scripts\activate` |
| Python 3.11 项目 | `py -3.11 -m venv .venv`<br>`.venv\Scripts\activate` |

---

### 场景九：Java 版本切换

**需求**：不同项目使用不同 JDK

**配置步骤**：

| 配置名称 | 启动命令 |
|----------|----------|
| Java 8 项目 | `$env:JAVA_HOME = 'C:\Program Files\Java\jdk1.8.0_361'`<br>`mvn clean install` |
| Java 17 项目 | `$env:JAVA_HOME = 'C:\Program Files\Java\jdk-17'`<br>`gradle build` |

---

### 场景十：Docker 快速启动

**需求**：快速启动常用容器

**配置步骤**：
1. 名称：`PostgreSQL`
2. 分组：`Docker/数据库`
3. 启动命令：
   ```
   docker run -d --name pg -e POSTGRES_PASSWORD=secret -p 5432:5432 postgres:15
   ```

## 分组管理技巧

合理的分组让你快速找到需要的配置：

```
📁 我的项目
  ├── 前端开发
  ├── 后端开发
  └── 测试
📁 服务器
  ├── 测试环境
  └── 生产环境
📁 远程桌面
  └── 开发机
📁 工具
  ├── 环境初始化
  └── 批量操作
```

**创建分组**：在分组字段输入 `项目名/子项目`，如 `服务器/测试环境`

---

## 效率小贴士

- **命名清晰**：用 `"项目A-前端开发"` 而非 `"dev1"`
- **善用分组**：项目多了以后，分组是快速定位的关键
- **密码安全**：密码使用 Windows DPAPI 加密，仅本机可用
- **同步备份**：将 Profiles 目录放到 OneDrive 可自动同步
- **版本管理**：推荐使用 nvm-windows/fnm 管理多语言版本，配合配置实现自动切换
