# TerminalBuddy v1.8.0 功能更新清单

> 发布日期：2026-10-21

本版是 v1.7.0 之后约两周、120 余个提交的集中发布：AI 工作流（供应商与模型配置、Agent 管理、Codex 历史、任务摘要）全面增强，Docker/Linux 部署链路成型（飞牛一键部署与本地自更新），Web 端登录与会话恢复体验大幅改善。

---

## 🧠 大模型供应商管理与模型配置

v1.8.0 的核心功能线。把 Claude / Codex 的模型接入从「手改配置文件」升级为应用内的供应商体系。

- **供应商体系**：新增全平台大模型供应商管理，数据落盘 `llm_providers.json`；支持供应商增删改查、API Key 加密存储、模型列表、每模型上下文窗口与推理等级；启动终端时把「供应商引用」展开为临时 settings 文件经 `--settings` 注入，官方优先级覆盖、不触碰用户自有 hooks 配置
- **Claude 默认配置面板**：`~/.claude/settings.json` 图形化读写，深合并写回并自动保留最近 10 份快照备份，改坏了可以回溯
- **指定模型启动**：连接 / 项目右键菜单新增 Claude 模型子菜单，指定模型启动并继承原命令参数；恢复历史会话同样可指定模型；标签栏与侧栏以描边「模型 chip」展示所用模型，不再拼进标签标题
- **推理档位（effort）与模型锚定**：五档 effort（low/medium/high/xhigh/max）全部写 env 键压制用户级残留档位；四档默认模型与子代理模型全部锚定为所选模型，避免 /model 切换或后台子任务被残留值引到不存在的模型；env 键与文件键不一致时给出冲突提示并支持一键清除
- **Codex 供应商与推理等级**：Codex 支持多模型供应商配置、逐行编辑模型并持久保存供应商模型列表；每个模型可单独配置推理等级（默认 MAX）；保存与快速启动时自动生成 Codex 模型目录；项目启动菜单支持 Claude / Codex 供应商双向切换

## 🤖 Agent CLI 管理

- **Agent 管理页**：桌面端原「容器环境」页重构为 Agent 管理：自动检测 Claude Code / Codex CLI 安装状态与可执行路径（覆盖 Windows 上 npm 的 .cmd/.bat/.ps1 shim 与 winget / Volta / pnpm / scoop 等非常规安装目录），应用内直接安装 / 升级，后台执行互斥防并发
- **逐项检查更新**：各 CLI 显示当前版本并支持按条目检查更新；关闭弹窗后安装 / 更新继续后台轮询
- **交互细节**：Provider 支持拖拽排序；新增可自由输入的模型组合框；「容器环境检测」从标题栏弹窗迁入设置页独立分项，Claude 模型配置按钮统一跳转设置页供应商
- **Web 端同步**：Web 端同步 Agent / Provider 管理面板，新增活动状态 WebSocket 实时推送

## 📚 Codex 会话历史与恢复

- **历史索引**：新增 Codex 会话历史服务，扫描索引 `CODEX_HOME` 下的 rollout 会话文件（自动去重备份副本），支持列表 / 全文搜索 / 重命名 / 置顶 / 删除 / 导出；复用 Claude 历史面板与回放页，体验对齐
- **一键恢复**：历史会话按项目目录自动匹配 Profile，在新终端以 `codex resume` 续接

## 📋 任务摘要与会话标签

- **任务摘要**：终端启动时记录 terminal ↔ Claude / Codex 会话绑定，从会话转录头部 / 尾部截取提示词生成任务标题（限制读取量，不加载整段长对话）；桌面标题栏、会话树与 Web 手机终端页均显示，外观设置可开关
- **会话标签布局**：Web 横向页签内嵌单行摘要；桌面纵向会话树改双行布局（第一行 = 任务摘要，第二行 = 工具与模型），Codex 会话区分专属配色；修复首次启动布局塌陷
- **窗口标题**固定为 TerminalBuddy，不再动态跟随摘要；手机端浏览器主页标题恢复使用设置值

## 🔄 容器重启后恢复会话（Web 端）

- **会话登记**：后台定时把运行中 Claude 终端的 session ID 落盘登记；容器重启后网页端按已保存页签自动重建终端、`claude --resume` 续接会话并正确归组
- **并发保护**：恢复流程加入一次性租约机制，多个浏览器客户端不会并发重复重建同一终端
- **落盘时机**：关闭会话时立即冲刷防抖写入，最后改名的页签不再丢失

## 🐳 Docker / Web 手机版

- **手机 SPA 分流**：手机访问按 User-Agent 自动分流至独立手机 SPA（`/m/`），Dockerfile 同时构建桌面与手机两套前端
- **手机端功能补齐**：项目与命令管理（长按菜单、项目编辑器、服务器路径选择器）；手机设置页接入 Claude / Codex 供应商管理
- **多挂载目录选择项目**：新增目录浏览服务，解析 mountinfo 自动发现容器内多个 Docker 挂载目录作为 Web 项目选择器的浏览根，含 `..` / 符号链接越界防护
- **触摸与输入修复**：触摸滚动向输入框注入 `NaN` 坐标、手机网页 Codex TUI 滚动方向相反、终端版本回包污染 Codex 输入框、中文 IME 候选窗锚点越界与组合预览撑宽导致的横向滚动
- **会话权限**：允许手机端关闭电脑浏览器创建的 Web 任务；修复终端回放错位与重连尺寸同步、输入实时同步与中文组合提交

## 🐮 飞牛 fnOS 一键部署与本地自更新

- **`deploy-fnos.sh` 一键部署**：把 TerminalBuddy 部署到飞牛 NAS，与 CentOS 实例并存；飞牛默认禁止 root 登录，脚本以普通管理员账号 + `sudo` 完成，**不需要**在飞牛上安装 Node.js 或 Rust；首次运行自动生成部署密钥并安装公钥，之后全程免密，sudo 密码只经 stdin 传递、临时文件用 trap 清理
- **默认在飞牛上编译镜像**：部署机无需 docker / Node / Rust，任意能 ssh 的机器都能发包，源码包约 16MB；i3-N305（8 核）首次构建约 20-40 分钟，之后源码指纹未变时跳过构建直接复用镜像；基础镜像沿用「本地命中 → 离线备份 → 备用镜像源」三级兜底；需要复用本机 Docker 层缓存时用 `--build-local`
- **`scripts/deploy-fnos-remote.sh`**：远端以 root 运行，负责目录属主、生成 `compose.fnos.yaml`、构建或载入镜像、按源码 / 镜像 / 配置指纹决定是否重建容器、健康检查与容器内 Docker socket 校验
- **飞牛 TrimACL 适配**：`/vol1` 以 TrimACL 判定权限（`setfacl` 无效），部署时改用容器内 uid 1000 对 data / home / workspace 三个目录做**实际写入探测**，失败即中止并给出补救命令；工作区与容器内同路径挂载，保证终端里 `docker compose` 的相对目录挂载落到正确的宿主机路径
- **`update.sh` 本地自更新**：在宿主机或网页终端直接执行即可换镜像升级；先 `docker inspect` 校验旧容器挂载 / socket / 网络作为回退基线，构建新镜像切换服务，**失败自动回退旧镜像旧容器**；更新成功后保留交互式终端
- **网页端自更新体验**：新增更新状态接口，前端独立更新监视组件；自更新导致 WebSocket 断开时页面保持「构建镜像 / 切换服务」进度浮层与完整更新日志，回退或恢复后自动重连，不再白屏

## 🔐 Web 登录状态长期保持

- **登录有效期延长至 30 天**：JWT 有效期由 24 小时改为 30 天（`web/auth.rs` 的 `TOKEN_TTL_DAYS`），不再频繁要求重新登录
- **重启后保持登录**：JWT 签名密钥持久化到数据目录 `jwt.key`（容器内 `/data/jwt.key`，权限 600），替换原先每次启动随机生成密钥的行为；此前服务一重启所有已登录设备都被强制退出，现在重启服务、重建容器后 token 依然有效
- 密钥文件损坏时明确报错而**不**静默换新密钥，避免无声地把所有设备踢下线；新增单元测试锁定 30 天有效期与换密钥验签失败的边界行为
- token 从 sessionStorage 迁到 localStorage，与 30 天有效期配合，关闭浏览器不再掉线

## 🛡️ Web 端权限与登录加固

- **只读权限实时化**：终端只读权限改用 ref 实时读取，同步禁用 stdin、粘贴、图片插入、拖放与命令补全，杜绝闭包过期导致的越权输入
- **局域网 http 兼容**：非安全上下文下补 `getRandomValues` 垫片，修复 `crypto.randomUUID` 缺失导致点击「启动终端」无反应
- **登录页细节**：移除恒定的用户名输入框；修复初始密码输入框无法右键粘贴
- **Docker 版可管理**：支持管理员修改登录密码与浏览器主页标题自定义

## 🚚 部署与构建

- **Linux 版本适配**：后端拆出独立 server 运行时（桌面 / 无头双形态），新增多阶段 Dockerfile、compose 与一键部署脚本（`deploy-centos.sh` / `DEPLOY_README.md`）
- **CentOS 部署两段式重构**：拆为「发起端 → 目标端」两段脚本，工作区路径安全校验提前（避免 chown 指向系统目录）、镜像源多写法兼容、端口占用检查、源码指纹未变时不中断服务
- **Windows 单文件 exe 交叉编译**：新增 `build-windows-exe.sh` + `scripts/windows-build/`（cargo-xwin 一次性 Docker 容器），Linux 上即可产出 Windows exe；源码只读挂载，宿主机不安装工具链，仅输出到 `dist/`（含 sha256 校验），不生成安装包
- **Docker 镜像构建导出**：`build-docker-image.sh` 一键构建并导出 tar / tar.gz 离线包

## 📌 升级提示

- **Windows 桌面版**：可直接覆盖安装；新增 `llm_providers.json`（供应商数据）自动创建；`~/.claude/settings.json` 图形化写入前会自动备份快照，其余数据结构无变化
