# 原生会话：任务清单与子代理面板实施计划

制定日期：2026-11-09。前置调研见对话记录，关键结论：CLI 早已通过 `task_*` 事件与 `TodoWrite` 工具输出完整状态，后端把它们压平成中文工具消息后丢弃，前端因此既没有进度视图也没有「派发了哪些子代理」的入口。

> 本计划只描述实施步骤，不包含代码改动。文件路径相对仓库根目录，行号以制定日代码为准。

## 2. 目标与验收标准

### 2.1 验收标准

1. 回合运行中，输入框上方始终有一行折叠态进度：`3/7 · 正在 实现 TodoWrite 解析 · ▓▓▓░░`；展开后逐条显示 pending / in_progress / completed，状态样式见 6.1。（`✓ 3/7` 的勾选形式只在全部完成时出现，见 6.1 文案规则。）
2. `TodoWrite` 被调用后 1 秒内清单更新；同一回合多次调用以**最后一次全量快照**为准，不叠加、不残留旧条目；正文中不出现 `TodoWrite` 工具条目。
3. 派发子代理后，底部出现 chip：`● Explore 执行中 42s`；结束时变为「已完成 / 失败 / 已停止」，运行中 chip 实时显示已等待秒数（秒数只重渲染 chip 自身）。
4. 点击 chip 打开右侧抽屉，展示该子代理的完整工作过程；主列表滚动位置与虚拟化状态不变。窄屏（< 640px）抽屉铺满宽度，同样不退回跳转。
5. 会话切走再切回、刷新页面、`/clear`、`--resume` 恢复后，清单与 chip 状态不出现「幽灵条目」（已结束的仍在跑、已清的仍显示）；抽屉随会话切换自动关闭。
6. 旧会话 JSON、旧版 CLI（无 `task_*` 事件）、从不使用 TodoWrite 的会话：界面不出现空壳，不报错。
7. 流式期间无可见性能回退：任务清单/子代理状态更新不得逐帧触发整页重渲染，`AgentMessageList` 的虚拟化高度缓存不得失效。
8. `npx tsc --noEmit`、`cargo check`、`cargo test --lib` 全绿；新增 Tauri 命令（如有）通过 `python scripts/check-invoke-coverage.py`。
9. 键盘可达：清单卡、每个 chip、抽屉关闭按钮都能 Tab 聚焦并显示焦点环，`Esc` 关闭抽屉后焦点回到触发它的 chip。
10. 深浅色两套主题下均无写死色值：所有颜色来自 6.0 的令牌或 `color-mix`。

### 2.2 非目标质量线

- 不引入新的前端依赖（清单卡与 chip 用 CSS + lucide 图标即可）。
- 不改变现有消息协议语义：`messages` 数组结构不动，新增信息放会话级字段。

## 4. 数据结构设计

### 4.1 Rust（`models/ai_chat.rs`）

```rust
/// 会话当前任务清单：TodoWrite 全量快照的直接投影。
#[derive(Clone, Debug, Serialize, Deserialize, PartialEq, Eq)]
#[serde(rename_all = "camelCase")]
pub struct AiTodo {
    pub content: String,                       // 命令式，如「修复登录跳转」
    pub status: String,                        // pending | in_progress | completed
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub active_form: Option<String>,           // 进行中文案，如「修复登录跳转」
}

/// 本轮派发过的子代理。运行态由 task_* 事件维护，结束后保留供回看。
#[derive(Clone, Debug, Serialize, Deserialize, PartialEq, Eq)]
#[serde(rename_all = "camelCase")]
pub struct AiAgent {
    pub task_id: String,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub tool_use_id: Option<String>,           // 关联 Task tool_use，与 subagentKey 的 parent 部分同源
    pub name: String,                          // subagent_type，缺失回落 "subagent"
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub description: Option<String>,
    pub status: String,                        // running | completed | failed | stopped | killed | paused
    #[serde(default)]
    pub background: bool,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub parent_task_id: Option<String>,        // 嵌套子代理
    #[serde(default)]
    pub depth: u32,
    pub started_at: i64,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub ended_at: Option<i64>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub summary: Option<String>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub duration_ms: Option<i64>,
    #[serde(default, skip_serializing_if = "Option::is_none")]
    pub tool_uses: Option<i64>,
}
```

`AiSession` 新增两个字段（与既有可选字段同风格）：

```rust
#[serde(default, skip_serializing_if = "Vec::is_empty")]
pub todos: Vec<AiTodo>,
#[serde(default, skip_serializing_if = "Vec::is_empty")]
pub agents: Vec<AiAgent>,
```

必改的连带点：

- `AiSession::metadata()` 带上这两个字段（实时帧要更新底部面板）。
- `persist_data` 的隐藏字段白名单不需要加（它们本就序列化）；但要确认 `serde_json::to_value` 路径无遗漏。
- 所有构造 `AiSession { .. }` 的位置补 `todos: Vec::new(), agents: Vec::new()`：`new_session`、`resume_from_history` 相关构造、测试夹具。

### 4.2 TypeScript（`services/tauri/aiChat.ts`）

新增 `AiTodo`、`AiAgent` 接口，`AiSession` 上加可选 `todos?: AiTodo[]; agents?: AiAgent[];`。`AiMessage` 不改。

### 4.3 安卓

本轮不改。`ApiJson` 配置了 `ignoreUnknownKeys = true`，新增字段被忽略；后续如需展示再做。

## 5. 解析设计

### 5.1 TodoWrite

- 位置：`ClaudeOutputState::assistant` 的 `kind == "tool_use"` 分支。
- 识别 `name == "TodoWrite"`，读 `item["input"]["todos"]`，映射为 `Vec<AiTodo>` 后 `data.todos = ...`（**整体替换**），再 `touch()`。
- **工具消息保留原文**（`TodoWrite\n{完整 input JSON}`），并在该消息上打 `todo` 标记（`AiMessage` 新增可选布尔字段 `todo: Option<bool>`，或复用现有的标记位；见 10 节决策 A）。保留原文是为了历史恢复时能还原清单（5.4）。
- 对应 `tool_result` 消息同样打标记，保持与工具调用配对。
- 前端不渲染这条工具消息与其 result：在 `NativeChatPage` 的 `blocks` 分组阶段直接跳过带 `todo` 标记的消息，避免与清单卡重复。

### 5.2 `TaskCreate / TaskUpdate / TaskList`（P2）

新版 CLI 并行存在这组增量工具。设计与 TodoWrite 共用 `todos`：

- `TaskCreate`：`{ subject, description, activeForm }` → 追加一条 `pending`。
- `TaskUpdate`：`{ taskId, subject?, status?, activeForm? }` → 按 id 定位更新。
- `TaskList`：结果解析成本高，暂不处理（只读工具，不影响状态）。

需要额外的内部映射 `taskId → todos 下标`，只放在 `ClaudeOutputState`，不落盘。若同一回合两种工具混用，以**最后一次写入**为准（TodoWrite 会整体覆盖）。

### 5.3 子代理状态

- 用一个新的 `ClaudeAgents` 状态结构（不要塞进 `ClaudeBackgroundTasks`，`awaited` 口径差异见本节末段）：
  - `task_started`：`task_id` 不在 `agents` 中则插入，`status: "running"`，`started_at = now`，记录 `tool_use_id / name(subagent_type 或 description) / description / is_backgrounded / parent_task_id / spawn_depth`。已存在则只更新可变字段（CLI 可能重发）。
  - `task_updated`：按 `patch` 合并；`status` 缺失时保持原值。
  - `task_notification`：置终态（`completed|failed|stopped`）、`ended_at`、`summary`、`duration_ms`、`tool_uses`。
  - `background_tasks_changed`：**快照校准**——快照里不存在的 `agents` 条目标 `stopped` + `ended_at`，不删除（要给人看历史）；新出现的补 `running`。注意快照里 `ambient == true`（内部杂务）与 `skip_transcript == true` 的条目**不进 `agents`**。
- `awaited == true` 的处理：这类是「前台阻塞等待的 resumed 子代理」。`ClaudeBackgroundTasks` 过滤它是为了算「后台任务未完成」，正确；`agents` **不过滤**——它也是被派发的子代理。两套过滤必须分开写并在注释里写明原因。
- 与消息的关联：`tool_use_id` ↔ `subagentKey` 的 `parent` 部分相等（`subagentKey = "{turn}:{parent_tool_use_id}"`），抽屉视图据此筛消息。
- 状态变更同样 `touch()`；`agents` 内的 `status` 变化必须进入增量推送（`Emitted` 只比对消息，`agents` 靠 revision，`touch` 保证 revision 变化即可）。

### 5.4 恢复与历史

- `--resume` / 历史恢复预填后，`todos` 为空。回填规则：倒序扫 `data.messages`，找到最后一条带 `todo` 标记的工具消息，解析其正文第二行的 JSON 还原 `todos`（这是 5.1 保留原文的原因）。解析失败时静默跳过，不影响会话加载。
- `agents` 不从历史回填：历史里的子代理已结束，意义不大，正文中的 `SubagentGroup` 仍可查看。

### 5.5 Codex

- 先抓真实事件：起一个 Codex 会话，让模型生成计划（`update_plan`），把 `codex app-server` 的原始事件落一份样本（存到 `docs/` 或临时目录，不入库）。
- 按 `apply_codex_event` 的 `item()` 分支加 `"plan"` / `update_plan` 映射到 `todos`（step→content，status 直映）。
- Codex 无子代理面板需求，`agents` 保持为空。

#### 三种行状态

| 状态 | 样式 |
| --- | --- |
| `completed` | `--text-tertiary` + 删除线（描边淡化）；标记 `✓` 用 `--success` |
| `in_progress` | `--text-primary` + **600 加粗**；标记为圆形，accent 22% 底、accent 文字，1.6s 呼吸 `box-shadow` 脉冲 |

#### 文案规则

| 时机 | 折叠态文案 | 计数胶囊 |
| --- | --- | --- |
| 存在 `in_progress` | `正在 <b>{activeForm ?? content}</b>` | `{done}/{total}` |
| 无 `in_progress`、未全完成 | `待开始：{首个 pending 的 content}` | `{done}/{total}` |
| 全部 `completed`，回合仍 `running` | `全部完成 · 用时 {mm 分 ss 秒}` | `✓ {total}/{total}` |
| 全部 `completed`，回合已 `idle` | 同上，整卡淡化（`--border-subtle`，背景透明） | `✓ {total}/{total}` |

- **`activeForm` 只用在折叠态**；展开列表一律显示 `content`（命令式），两者语义不混用。
- `TodoWrite` 的工具消息与其 `tool_result` **不在正文渲染**（见 5.1），避免清单卡与正文重复。
- 展开态按会话记忆：`localStorage` key `agent-todo-open:{sessionId}`，读写包 `try/catch`。
- 自动展开一次：本回合首次出现 `in_progress` 时若用户未手动收起过，则展开；用户手动收起后不再自动展开。
- 全部完成且回合 `idle`：**保持展开 3 秒，然后收起为单行**并淡化。
- `todos` 为空（长度 0）：整卡不渲染，不占高度。

### 6.2 子代理 chip 带

位置：清单卡下方、排队消息之上。

```
● Explore 执行中 42s   ● general-purpose 已完成 1m12s   ● code-reviewer 失败   +2
```

#### 结构

| 元素 | 规格 |
| --- | --- |
| 容器 | `display: flex; flex-wrap: wrap; gap: 6px`；`agents` 为空时整块不渲染 |
| chip | `padding: 4px 10px`；`radius: 999px`；`border: 1px solid color-mix(子代理 30%, --border-subtle)`；`background: color-mix(子代理 6%, transparent)`，hover 13% |
| 选中态 | `aria-pressed="true"`：边框用纯子代理色，背景 16% |
| 状态点 | 7px 圆点，`flex-shrink: 0` |
| 名称 | 600 字重，`--text-primary`，11.5px |
| 元信息 | `--text-tertiary`，`font-variant-numeric: tabular-nums` |

#### 四种状态

| 状态 | 表现 |
| --- | --- |
| `running` | 子代理紫点 + 呼吸动画；文案 `执行中 {m}m{s}s` |
| `completed` | `--success` 点；文案 `已完成 {m}m{s}s`（取 `duration_ms`） |
| `failed` | `--danger` 点与边框；文案 `失败` |
| `stopped` / `killed` / `paused` | `--text-tertiary` 点；文案 `已停止` |

#### 行为

- **秒表**：运行中 chip 内部 `useState + setInterval(1000)`，每秒只更新自己那段 `<span>` 文本；父组件不持有 clock（同 `ElapsedBadge`，审查 V-16）。
- **排序**：运行中按 `startedAt` 升序在前，已结束按 `endedAt` 降序在后。
- **数量**：最多平铺 4 个，其余收为 `+N`；点击 `+N` 展开全部（本次会话内记忆），展开后按钮变为「收起」。
- **保留时长**：已结束的 chip 在界面保留 **10 分钟**后由组件内定时淘汰；该淘汰只是显示层，`agents` 数据仍随会话保留，刷新后由 `agents.status` 重建。
- **只显示 `depth == 1`** 的顶层代理；嵌套代理只在抽屉里按层级展示。
- **点击**：打开抽屉；再次点击同一个 chip 关闭（`aria-pressed` 同步）。
- 无障碍：chip 是原生 `<button>`，Tab 可达；`aria-label` 为「{名称}，{状态}，{耗时}」。

### 6.3 子代理抽屉

**M3（低成本）**：点击先走 `listRef.current.jumpTo(该组首条消息 id)`，复用现有 `jumpTo`（`AgentMessageList.tsx:426`），同时把该 `SubagentGroup` 的 `toolOpenState` 置为展开。M4 落地后由抽屉取代，`jumpTo` 保留给键盘用户的次选路径。

**M4（目标形态）**：

| 项 | 规格 |
| --- | --- |
| 位置 | `.agent-chat-body` 内绝对定位，`top: 0; right: 0; bottom: 0`，`z-index: 8` |
| 宽度 | `min(440px, 78%)`；容器 < 640px 时 `width: 100%`（**全屏抽屉，不退回 jumpTo**） |
| 层级表达 | **无全屏遮罩**。左侧 1px `--border` + 向左 14px/34px 投影区分层级；主列表保持可见、可滚动，方便对照上下文 |
| 动画 | `translateX(24px) + opacity 0 → 0 / 1`，220ms；窄屏直接出现 |
| 头部第一行 | 状态点 + 名称（子代理紫，600，13px）+ 状态徽章 + 右侧 `✕ 关闭` |
| 头部第二行 | `description · 开始时间 {HH:mm} · 耗时 · 工具次数 · 深度`，11px、`--text-tertiary`、tabular-nums；字段为空时跳过该段（不显示占位符） |
| 正文 | 按 `subagentKey` 过滤 `messages`，顺序同主列表；复用 `ToolMessage` / `ChatMarkdown`，不新建渲染逻辑 |
| 工具条目 | 默认收起；单条 tool_result 超过 200 字符截断，与主列表一致 |
| 嵌套代理 | `depth > 1` 的内容左侧 2px 子代理色竖线 + 12px 缩进，条目标题前缀 `↳` |
| 关闭方式 | `✕` 按钮 / `Esc` / 再次点击同一 chip |
| 焦点 | 打开时聚焦关闭按钮；关闭后焦点回到触发它的 chip |
| 与主列表 | 打开不改 `scrollTop`、不卸载主列表（虚拟化状态不丢）；滚动主列表不关闭抽屉 |
| 自动关闭 | 切换会话、或 `subagentKey` 在 `messages` 中已不存在（`/clear`、恢复）时关闭 |
| 空态 | 只派发未产生消息的代理显示一行「该子代理尚未产生输出」 |

**实现提示**：抽屉只读 `messages` 做过滤渲染，不触碰 `AgentMessageList` 的 `range`；单个子代理消息量通常 < 200 条，不做虚拟化；超过 300 条时按主列表同样的截断策略处理更简单。

## 9. 风险与缓解

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| `agents` 状态遗漏 `touch()`，前端不刷新 | 面板停在旧状态 | 状态写入统一走一个小函数 `update_agents(cell, |data| ..)`，内部保证 `touch` |
| 与 `ClaudeBackgroundTasks` 的 `awaited`/`ambient` 口径混用 | 后台任务提前判定结束 → 回合误结束 | 两套结构独立，5.3 任务单独回归现有后台任务测试 |
| 快照 `background_tasks_changed` 与增量事件乱序 | 幽灵「执行中」 | 以快照为准做校准，缺项置终态而非删除；`run_id` 只用于去重，不上抛 |
| TodoWrite 原始 input 的留存 | 恢复会话清单为空 | 已在 5.1 定为保留原文 + `todo` 标记（决策 A），恢复时据此回填 |
| 流式期间 `todos` 每帧变化 | 整页重渲染 | TodoWrite 是回合内低频事件；agent 状态也只在事件到达时写，不做轮询 |
| 抽屉与虚拟化冲突 | 主列表跳位 | 抽屉只读 `messages` 过滤，不触碰 `AgentMessageList` 的 range |
| Codex 事件格式未经验证 | 映射错误 | 5.1 先抓真实样本，M5 不作为前置依赖 |

## 10. 已定决策

以下原为开放问题，现按 UI 稿（`design/native-chat-todo-subagent/index.html`）定稿，实施时不再另行确认：

1. **TodoWrite 原始 input 的留存方式**：采用**方案 A** —— 工具消息保留原文（`TodoWrite\n{json}`）并在消息上打 `todo` 标记，前端 `blocks` 分组时连同其 `tool_result` 一起跳过渲染，历史恢复时据此回填。不扩大 `AiMessage` 模型。
2. **已结束 chip 的停留时长**：**10 分钟**，纯前端淘汰，`agents` 数据仍保留。
3. **窄屏抽屉**：< 640px 时**铺满宽度**，不退回 `jumpTo`。
4. **抽屉宽度**：`min(440px, 78%)`。
5. **抽屉遮罩**：**不加全屏遮罩**，改用左侧描边 + 投影区分层级，保持主列表可见可滚动。
6. **`TaskCreate / TaskUpdate`**：仍归 P2；若实测模型更常用它们，再提前到 M2。
7. **安卓**：本期只做 M5.3 的只读清单，不做抽屉。
