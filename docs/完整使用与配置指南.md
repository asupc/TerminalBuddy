# TerminalBuddy 完整使用与配置指南

> 适用版本：TerminalBuddy 1.4.0，Windows 桌面版。
>
> 本指南覆盖 PowerShell、PowerShell 7、CMD、本地文件管理、Git、文本编辑、Claude Code、机器人通知、Web 访问以及数据备份。连接部分只讲本地终端和远程桌面（RDP）。

本文以长期、高频使用场景为基础整理：使用独立同步目录保存数据，按多级分组维护大量本地终端配置，通过启动命令快速进入工作状态，并启用标签恢复、Claude Code 通知和 Web 访问。文中的目录、主机、账号、命令和颜色均为通用占位示例，不对应任何真实数据。

## 1. 安装与首次启动

### 1.1 安装

1. 打开 [TerminalBuddy Releases](https://gitee.com/updateme/terminal-buddy/releases)。
2. 下载最新的 Windows NSIS 安装包。
3. 运行安装程序并启动 TerminalBuddy。
4. 后续可以通过标题栏的“检查更新”按钮查看新版本；更新仍需打开发布页下载安装。

从旧版本升级时通常可直接覆盖安装，不必先卸载。覆盖安装不会主动删除用户数据，但升级前仍建议按本文“数据与备份”章节做一次完整备份。

### 1.2 首次配置顺序

建议严格按以下顺序设置，避免后期迁移遗漏数据：

1. 在“设置 -> 数据管理”中确定数据目录。
2. 在“设置 -> 行为设置”中确定界面、标签、启动和关闭行为。
3. 新建本地终端配置并规划分组。
4. 配置命令模板与启动参数预设。
5. 按需配置 Claude Code Hook、机器人通知和 Web 管理。
6. 完成一次完整备份并验证恢复路径。

如果准备把数据放到 OneDrive 或其他同步盘，最好在创建连接前就选好同步目录。

## 2. 界面速览

TerminalBuddy 的主要区域如下：

| 区域 | 主要用途 |
|---|---|
| 标题栏 | 切换连接面板、文件面板、分屏、皮肤，查看 AI 用量、更新与设置 |
| 连接面板 | 按分组管理和启动终端配置 |
| 文件面板 | 管理常用目录、浏览文件、打开编辑器和使用 Git 工具栏 |
| 选项卡区 | 在终端、编辑器和 Git 历史页面之间切换 |
| 主工作区 | 显示终端、文本编辑器或 Git 历史 |

“设置 -> 行为设置 -> UI 样式”提供两种布局：

- “默认”：连接、文件、选项卡为独立面板，设置按钮位于标题栏。
- “侧边栏”：入口集中到类似 VS Code 的左侧活动栏，更适合窄屏或经常切换面板的场景。

面板宽度可以拖动调整，程序会保存宽度。按 `F11` 可进入专注模式，隐藏或恢复侧边面板与标签栏。

## 3. 推荐的基础配置

下面是一套适合“多项目、多本地终端、经常恢复会话”场景的基线。它参考了成熟使用习惯，但不复制任何个人数据。

| 设置 | 推荐值 | 原因 |
|---|---|---|
| 数据存储路径 | 独立目录，如 `D:\Sync\TerminalBuddy` | 便于备份和同步，不与安装目录混在一起 |
| UI 样式 | 默认 | 多面板并行查看时信息密度更高 |
| 终端加载方案 | VS Code，可用时启用 | ConPTY 兼容性和交互体验更接近 VS Code |
| 启动窗口模式 | 最大化启动 | 适合多面板和分屏 |
| 终端跟随应用主题 | 开启 | 未单独指定主题的连接自动保持一致 |
| 启动时恢复选项卡 | 开启 | 恢复上次工作现场 |
| 自动恢复 Claude Code 会话 | 开启 | 对已识别会话使用 `claude --resume` |
| 启动时展开连接面板 | 开启 | 启动后直接选择项目配置 |
| 启动时展开文件面板 | 按需，通常关闭 | 项目较多时减少初始界面拥挤 |
| 关闭时最小化到托盘 | 按需 | 需要后台 Web 或机器人服务时建议开启 |
| 纵向选项卡 | 开启 | 标签较多时比横向标签更易扫描 |
| 右键粘贴 | 开启 | 提高终端操作效率 |
| 双击运行 `.bat` | 关闭 | 避免误执行，双击时先在编辑器检查 |
| 仅单窗口运行 | 开启 | 减少同一设备并发写数据的风险，修改后需重启 |
| 开机自动启动 | 按需 | 需要持续提供 Web 或通知服务时再启用 |
| 单屏 / 两栏 / 四格字号 | `14 / 12 / 11` | 当前默认值，兼顾密度与可读性 |
| Web 端口 | `9600` 或其他未占用高位端口 | 默认端口，便于局域网访问 |
| Web 会话策略 | 保持默认隔离 | 降低浏览器误操作桌面终端的风险 |

“VS Code”加载方案只有在检测到可用的系统 Node.js 和 TerminalBuddy 终端插件时才能选择。如果设置页提示不可用，先使用“默认”方案，不影响其他功能。

## 4. 创建和组织连接

### 4.1 新建连接

可以从连接面板的新建按钮、连接面板空白处右键菜单，或“设置 -> 连接管理 -> 新建连接”进入编辑器。

本指南涉及的连接类型如下：

| 类型 | 用途 | 前置条件 |
|---|---|---|
| PowerShell | Windows PowerShell 5.x | Windows 自带 |
| PowerShell 7 | 现代 PowerShell，即 `pwsh` | 需要已安装 PowerShell 7 |
| CMD | 传统命令提示符 | Windows 自带 |
| 远程桌面（RDP） | 启动 Windows `mstsc.exe` | 目标主机允许远程桌面 |

### 4.2 本地终端字段

PowerShell、PowerShell 7 和 CMD 共享以下字段：

| 字段 | 说明 |
|---|---|
| 名称 | 连接面板和选项卡显示名称；同一分组内不能重名 |
| 分组 | 支持多级分组，使用 `/` 表示层级 |
| 启动命令 | 终端创建后自动依次写入的命令，可拖动排序 |
| 环境变量 | 仅注入该配置启动的终端，不修改系统全局环境 |
| 起始路径 | 终端启动时使用的工作目录 |
| 颜色主题 | 该终端独立使用的配色 |
| Tab 颜色 | 标签文字和活动指示的识别色 |

建议命名格式保持稳定，例如：

```text
分组：开发/项目甲
名称：项目甲 - PowerShell 7
起始路径：D:\Projects\ProjectA
```

不要把真实密码、Token 或 Cookie 放进名称、分组、启动命令和环境变量。启动命令、环境变量以及命令历史都可能持久化到数据目录。

### 4.3 启动命令的执行规则

本地终端的底层先创建 `cmd.exe`，然后按连接类型进入 PowerShell、PowerShell 7 或保留 CMD，再写入配置的启动命令。

使用时注意：

1. 启动命令会在终端创建约 300 毫秒后依次发送。
2. 前面的命令应能快速结束，交互式或长期运行命令应放在最后。
3. 多条命令不是事务，其中一条失败不会自动阻止后续命令。
4. 起始路径已由终端进程设置，不必再写一条重复的 `cd`。
5. 命令正文会进入持久化配置，不要直接写敏感凭据。

一个安全的通用示例：

```text
1. git status
2. <你的交互式工具命令>
```

### 4.4 环境变量

环境变量适合保存非敏感、配置级的行为开关，例如：

```text
NODE_ENV=development
PYTHONUTF8=1
```

环境变量保存在连接 JSON 中。即使目录位于个人同步盘，也应将其视为明文配置，不要存放长期有效的访问密钥。

### 4.5 远程桌面（RDP）

RDP 配置包括：

- 主机地址：必填，可以是 IP 或域名。
- 端口：默认 `3389`。
- 用户名：可选。
- 密码：可选，保存时使用 Windows DPAPI 加密。
- 分辨率：留空为全屏，也可选择固定分辨率。

启动 RDP 配置时，TerminalBuddy 会：

1. 将凭据写入 Windows 凭据管理器的 `TERMSRV/<主机>` 项。
2. 调用系统 `mstsc.exe`。
3. 同一配置对应的远程桌面窗口仍在运行时，再次启动会尝试把已有窗口切到前台。

DPAPI 加密绑定 Windows 用户环境。把配置同步到另一台电脑或换用另一个 Windows 账号后，原密码通常无法解密，需要重新填写。

### 4.6 大量连接的组织方式

连接较多时，推荐使用“场景 / 项目 / 角色”三级思路，而不是把所有配置放在默认分组：

```text
开发/项目甲
开发/项目乙
运维/桌面
工具/日常
归档/暂用
```

常用操作：

- 双击连接：直接启动。
- 右键连接 -> 启动：启动标准配置。
- 右键连接 -> 命令行：在该连接的起始路径打开普通命令窗口。
- 右键连接 -> 打开目录：在资源管理器定位起始路径。
- 右键连接 -> 复制启动路径：复制目录文本。
- 右键连接 -> 置顶：放到分组前部。
- 右键连接 -> 复制：派生一个相似配置。
- 右键连接 -> 重命名或按 `F2`：只修改显示名称。
- 右键分组：添加配置、添加子分组或重命名分组。
- 把连接拖到选项卡面板：立即创建对应终端。

复制已有配置再修改起始路径和启动命令，通常比反复从空白配置开始更高效。

## 5. 启动参数预设

“设置 -> 启动参数”用于给已有配置附加临时参数，而不必复制多个几乎相同的连接。

每个预设包含：

| 字段 | 说明 |
|---|---|
| 名称 | 同时作为选项卡上的标签显示 |
| 参数或完整命令 | 根据执行方式解释 |
| 执行方式 | “追加参数”或“独立命令” |
| 命令匹配 | 只在启动命令包含指定文本时显示该预设 |
| 标签颜色 | 区分不同启动模式 |

### 5.1 追加参数

“追加参数”会把参数追加到配置中的每一条启动命令后面。

例如，基础命令为：

```text
<tool>
```

预设参数为：

```text
--resume
```

启动时实际执行：

```text
<tool> --resume
```

如果一个配置有多条启动命令，同一段参数会追加到每一条命令。需要使用预设时，最好让该配置只包含一条目标启动命令。

### 5.2 独立命令

“独立命令”会忽略原配置的全部启动命令，只执行预设中填写的完整命令。它适合临时切换为另一套入口命令。

### 5.3 命令匹配

命令匹配只控制预设是否出现在连接右键菜单中，不会改变参数拼接规则。建议填入足够稳定且不含隐私的命令名，例如 `<tool>`。

创建预设后，右键连接即可看到“启动 + 预设标签”的入口。启动后的选项卡会保留预设标签和颜色，方便区分运行模式。

## 6. 终端日常操作

### 6.1 命令补全

输入命令时，TerminalBuddy 会结合内置命令、用户自定义命令和命令历史生成候选。

| 操作 | 效果 |
|---|---|
| `Tab` | 接受当前候选 |
| `Right Arrow` | 接受行内灰色补全文本 |
| `Up` / `Down` | 在候选列表中移动 |
| `Enter` | 当候选已显式选中时，先接受候选但不立即执行 |
| `Esc` | 关闭候选列表 |

候选只在终端处于普通命令输入状态时显示。全屏交互程序、编辑器或其他替代屏幕程序中不会强行弹出。

### 6.2 复制、粘贴与链接

- `Ctrl+C`：终端有选区时复制选中文本；没有选区时仍交给当前命令行程序处理。
- `Ctrl+V`：粘贴文本，也能识别从资源管理器复制的文件路径。
- 粘贴截图或图片时，会向终端写入 `[图片:<临时路径>]` 形式的引用。
- 多行文本使用终端的 bracketed paste 方式写入，仍应在执行前检查内容。
- 开启“右键粘贴”后，无选中文本时右键直接粘贴；有选区时保留右键菜单行为。
- `Ctrl+点击` 终端中的 URL：用默认浏览器打开。

不要在不可信终端中直接粘贴未检查的多行命令。

### 6.3 搜索输出

在终端聚焦时按 `Ctrl+F` 打开搜索栏，可在当前终端缓冲区中查找输出。按 `Esc` 关闭搜索或弹出层。

### 6.4 任务状态

终端执行任务时，标签旁的活动指示灯会变化。指示灯颜色可以跟随标签颜色，也可以在“行为设置”中指定统一颜色。

关闭正在执行任务的终端时，TerminalBuddy 会要求确认。此确认只表示即将关闭终端进程，不会自动保存终端内程序的未提交状态。

## 7. 选项卡、分组与分屏

### 7.1 纵向和横向选项卡

可以在“设置 -> 行为设置 -> 纵向选项卡”中切换，也可以使用选项卡区域的右键菜单切换。

选项卡常用操作：

- 单击：激活终端或编辑器。
- 鼠标中键：关闭。
- `F2`：重命名当前选项卡。
- 右键：重命名、以此配置新建、复制配置名、打开目录、复制启动路径或关闭。
- 横向选项卡还支持“关闭左侧”“关闭右侧”“关闭其他”。
- 编辑器文件有未保存修改时，标签显示脏状态，关闭前会确认。
- Web 创建的终端会显示 `Web` 标识；默认隔离模式下，桌面端只读。

`F2` 根据最后点击的区域判断重命名对象。先单击目标连接、分组、文件或选项卡，再按 `F2`。

### 7.2 分屏

标题栏的分屏按钮按以下顺序循环：

```text
单屏 -> 两栏（2x1）-> 四格（2x2）-> 单屏
```

进入分屏后：

1. 已有终端会进入分屏槽位。
2. 单击未显示在分屏中的其他标签，会把它放入可用槽位。
3. 单击已在分屏中的标签，只切换活动焦点。
4. 空槽位会保留，直到选择其他终端填入。
5. 退出分屏不会关闭终端。

“行为设置 -> 终端字号”可以分别设置单屏、两栏和四格字号，范围为 `8` 到 `32` 像素。

### 7.3 专注模式

按 `F11` 在普通布局和专注模式之间切换。专注模式隐藏连接、文件和标签区域，但不会关闭会话或改变分屏内容。

## 8. 本地文件面板

### 8.1 添加目录

点击文件面板顶部的“添加文件夹”按钮，可以：

- 从常用位置选择目录。
- 浏览选择任意目录。
- 手动输入绝对路径。

添加后的目录作为文件树根节点保存。可以同时维护多个项目根目录。

顶部工具栏还支持：

- 全部折叠。
- 刷新文件列表。
- 切换升序或降序。
- 在名称、类型等排序方式之间切换。
- 过滤父级目录。

### 8.2 文件和目录操作

右键根目录或普通条目可以执行：

- 刷新。
- 在当前目录打开命令窗口。
- 在资源管理器中显示。
- 在系统中打开文件。
- 重命名。
- 删除。
- 从文件列表移除根目录。

删除操作会修改真实文件系统，并在执行前确认。它不是“仅从列表隐藏”。

选中文件后按 `Ctrl+C` 可复制路径，按 `F2` 可重命名。把文件从文件树拖到终端，会把路径写入终端输入。

### 8.3 文件排除规则

在“设置 -> 文件排除”中配置文件树需要隐藏的内容：

| 示例 | 含义 |
|---|---|
| `node_modules` | 精确匹配文件或文件夹名称 |
| `*.log` | 匹配后缀 |
| `**/*.html` | 匹配指定扩展名路径 |

默认规则为 `node_modules` 和 `.git`。排除只影响文件树显示，不会删除文件，也不会改变 Git 行为。

## 9. 文本编辑器

双击文本文件会在主工作区打开 Monaco Editor。也可以在选项卡空白处右键新建一个文本编辑器标签。

常用快捷键：

| 快捷键 | 作用 |
|---|---|
| `Ctrl+S` | 保存文件 |
| `Ctrl+F` | 查找 |
| `Ctrl+H` | 查找并替换 |
| `Shift+Alt+F` | 格式化文档 |
| `Ctrl+/` | 切换行注释 |
| `Ctrl+Shift+V` | 切换 Markdown 预览 |
| `Ctrl+Z` / `Ctrl+Y` | 撤销 / 重做 |

Markdown 文件支持编辑器与预览双栏显示，分隔线可拖动或用键盘调整。若文件在编辑器外被修改，同时当前标签也有未保存更改，保存时会提示是否覆盖。

## 10. Git 图形界面

当文件面板当前目录属于 Git 仓库时，底部会显示 Git 工具栏。它只针对当前打开的目录或手动选择的仓库根目录。

主要功能：

- 查看当前分支、上游、领先和落后数量。
- 查看已暂存、未暂存和未跟踪文件数量。
- 展开分支列表并切换分支。
- 拉取远端更新。
- 提交全部变更或选中的文件。
- 预览推送目标、提交范围和命令后再推送。
- 打开提交历史图。
- 展开某次提交的文件列表并查看单文件差异。

使用建议：

1. 切换分支前先确认工作树状态。
2. 推送前检查预览中的远端、目标分支和待推送提交。
3. 提交部分文件时，确认选择列表没有遗漏相互依赖的修改。
4. Git 操作失败时，错误输出会按原文显示，便于回到终端继续排查。

## 11. 命令模板与历史

### 11.1 命令模板

“设置 -> 命令模板”展示内置分类和用户自定义命令。可以：

- 按命令或说明搜索。
- 添加自定义命令。
- 修改内置或自定义命令的说明。
- 隐藏不需要的内置命令。
- 恢复已隐藏的命令。
- 删除自定义命令。

命令模板的主要作用是为终端补全和连接编辑器中的启动命令建议提供数据，不会自动执行。

### 11.2 命令历史

终端在按回车执行时会记录命令历史，并用于后续补全。当前版本的历史主体保存在 `terminal_buddy.db` 中，而不是普通 JSON 文件。

历史中可能包含路径、参数和误输入的敏感文本，因此：

- 不要把数据目录或备份包公开分享。
- 不要把 Token 直接写在命令行参数中。
- 迁移或备份时应包含 `terminal_buddy.db`。

每个连接可以单独选择以下终端配色：

## 14. AI 用量

“设置 -> AI 用量”支持配置：

- 智谱 GLM API Key。
- 百度千帆 Cookie。
- DeepSeek 认证 Token。
- MiniMax API Key。
- 火山方舟 Cookie。

配置后，把鼠标停留在标题栏的 AI 用量按钮上即可查看面板。

安全提醒：这些值由桌面前端保存在数据目录的 `ClientData/settings.json` 中，不使用 DPAPI 加密，并且会进入应用的 JSON 导出文件。不要把该文件、同步目录或导出包分享给他人。凭据不再使用时，应在服务商后台主动吊销。

## 15. Claude Code Hook 与桌面通知

### 15.1 安装 Hook

进入“设置 -> Hook 设置”：

1. 选择 Claude Code 配置目录。留空时程序会尝试使用默认目录。
2. 点击“安装 Hook”。
3. 等待状态显示“已安装”。
4. 如显示“需要修复”，点击“修复 Hook”。
5. 如显示“配置异常”，先定位并修复 Claude Code 的 `settings.json`。

安装过程会在首次修改前创建 `settings.json.terminalbuddy.bak` 备份。Hook 用于识别：

- 会话开始和结束。
- 运行状态。
- 等待处理。
- 结构化决策。
- 任务完成。
- 执行失败。

卸载 Hook 会移除 TerminalBuddy 写入的 Hook 项。修改 Claude Code 配置前仍建议保留自己的独立备份。

### 15.2 通知延迟

Hook 设置可以分别控制：

- 等待处理通知及延迟秒数。
- 任务结束通知及延迟秒数。

延迟范围为 `0` 到 `3600` 秒。设置为 `0` 表示立即通知。正在查看的终端通常不会重复发送完成通知，以减少干扰。

## 16. 机器人通知

进入“设置 -> 机器人通知”后，先配置全局项：

- 启用机器人通知。
- 发送决策通知。
- 发送完成通知。
- 将回复写入终端后发送回车。
- 决策有效期，范围 `1` 到 `1440` 分钟。

当前界面支持以下通道：

| 通道 | 发送通知 | 接收远程回复 | 配置方式 |
|---|---|---|---|
| 飞书应用机器人 | 支持 | 支持 | 扫码或填写 App 凭据，使用长连接 |
| 微信机器人 | 支持 | 支持 | 扫码创建 iLink Bot，使用长连接 |
| 钉钉应用机器人 | 支持 | 当前按单向通道使用 | 扫码或填写 App 凭据，并填写收件人 `userId` |
| QQ 机器人桥接 | 由桥接端实现 | 支持 | 配置桥接发送 URL 和回调 Token |
| 通用机器人桥接 | 由桥接端实现 | 支持 | 配置桥接发送 URL 和回调 Token |

推荐配置流程：

1. 点击“新增通道”。
2. 选择平台并填写通道名称。
3. 优先使用扫码配置；必要时手动填写凭据。
4. 配置接收目标和允许回复的用户 ID。
5. 先发送测试消息。
6. 对支持双向决策的平台，再发送测试决策并完成一次回复。
7. 确认长连接显示“已连接”或回调地址可从桥接端访问。
8. 最后开启全局通知开关。

飞书和微信使用长连接接收事件，不需要公网回调。QQ 和通用桥接需要桥接端调用设置页显示的本机回调地址。

机器人 Secret 和回调 Token 使用 Windows DPAPI 加密，设置页不会回显已有 Secret。同步到另一台电脑后，应重新授权或重新输入凭据。

远程回复会进入真实终端。只允许受控的个人账号或群聊，谨慎开启“写入终端后发送回车”。完整的桥接协议和平台准备可参考 [机器人通知接入指南](机器人通知接入指南.md)，但应以当前设置页展示的通道类型和字段为准。

## 17. Web 远程访问

### 17.1 启动服务

进入“设置 -> Web 管理”：

1. 设置端口，界面允许范围为 `1024` 到 `65535`。
2. 设置用户名。
3. 首次启动前设置密码。
4. 点击“启动服务”。
5. 用同一局域网内的设备访问显示的地址，或扫描二维码。

服务监听 `0.0.0.0`，即所有本机网络接口。Windows 防火墙可能在首次启动时请求放行，也可能需要手动添加入站规则。

### 17.2 登录和快速访问链接

普通登录使用用户名和密码，密码以 bcrypt 哈希保存。

二维码和“免密访问”链接包含一个与正常登录等价的 JWT：

- 有效期为 24 小时。
- Web 服务重启后签名密钥变化，旧链接随之失效。
- 得到链接的人在有效期内可以跳过密码登录。

因此不要把二维码截图或完整链接发到不受信任的聊天、工单或日志中。

### 17.3 自定义 Host

服务启动后可以填写“自定义 Host”，格式为：

```text
地址:端口
```

例如：

```text
terminal.example.lan:9600
[2001:db8::10]:9600
```

该字段只改写界面显示、二维码和快速访问 URL，不会替你配置 DNS、端口转发、反向代理、TLS 或监听地址。

### 17.4 会话隔离

当前默认值为 `webApiShareSessions=false`，设置页没有公开的共享开关。默认行为是：

- Web 端只管理 Web 创建的终端。
- 桌面端可以看到 Web 终端，但不能写入、缩放或关闭，会显示只读状态。
- 浏览器窗口较小时只允许增大 PTY 尺寸，不会缩小桌面端终端。

这是更适合日常使用的安全策略。

### 17.5 网络安全

内置服务使用普通 HTTP，不提供 HTTPS。建议只在以下环境使用：

- 可信局域网。
- 已加密的组网或 VPN。
- 由可信反向代理提供 HTTPS 和访问控制的环境。

不要直接把端口映射到公网。停止使用时，在设置页点击“停止服务”，并确认托盘中的程序是否仍在运行。

如果 QQ 或通用桥接通道仍需要本机回调，关闭 Web 访问后，底层 HTTP 服务可能继续为机器人回调运行。需要完全停止监听时，还应停用对应机器人通道或退出 TerminalBuddy。

## 18. 数据目录与配置文件

### 18.1 默认目录和自定义目录

默认用户数据目录为：

```text
%APPDATA%\TerminalBuddy
```

选择自定义数据目录后，后端仍在默认目录保存一份控制设置，其中包含 `dataPath` 指针；主要用户数据写入自定义目录。也就是说，每台 Windows 设备第一次使用同一个同步目录时，都需要在本机设置一次数据路径。

### 18.2 当前数据结构

典型的数据目录如下：

```text
TerminalBuddy/
├── Profiles/                    # 连接配置，RDP 密码为 DPAPI 密文
├── Workspaces/                  # 兼容性数据，当前桌面 UI 没有独立管理入口
├── ClientData/
│   ├── settings.json            # 前端行为设置和 AI 凭据
│   ├── theme.json               # 应用皮肤
│   ├── saved_tabs.json          # 上次打开的标签
│   ├── bookmarks.json           # 文件目录书签
│   ├── file_nav.json            # 文件面板状态
│   ├── cmd_custom.json          # 自定义命令
│   ├── cmd_overrides.json       # 内置命令说明和隐藏状态
│   ├── extra_param_presets.json # 启动参数预设
│   └── ...
├── Bots/                        # 机器人通道配置，Secret 为 DPAPI 密文
├── terminal_buddy.db            # 命令历史、机器人决策绑定等 SQLite 数据
└── debug.log                    # 调试日志
```

旧版本升级后可能残留已停用的目录或旧 JSON 文件。TerminalBuddy 1.4.0 不再使用旧的 AI 交付数据和旧主题目录；不要把残留目录误认为当前功能入口。确认备份可用前不必急于手动删除。

### 18.3 两类 settings.json

当前版本存在两个不同用途的设置文件：

1. `%APPDATA%\TerminalBuddy\settings.json`：Rust 后端设置，包括自定义数据路径、窗口行为、Web 端口、用户名和密码哈希等。
2. `<数据目录>\ClientData\settings.json`：React 前端设置，包括界面行为、字体、通知开关和 AI 用量凭据等。

排查“某项设置没有随同步目录迁移”时，应先确认它属于哪一类设置。

## 19. OneDrive 或同步盘配置

### 19.1 推荐做法

可以把自定义数据目录放到个人 OneDrive、坚果云或其他同步盘，但应遵守以下规则：

1. 每台设备分别在设置页选择同一个已同步目录。
2. 同一时刻只在一台设备上运行 TerminalBuddy。
3. 切换设备前彻底退出程序，不要只关闭到托盘。
4. 等同步客户端显示同步完成后，再在另一台设备启动。
5. 出现“冲突副本”时先停止两端程序，再人工判断保留哪份数据。
6. 不要用公共共享目录同步，因为目录中含命令历史和凭据材料。

这些限制很重要，因为 `terminal_buddy.db` 使用 SQLite WAL 模式。同步盘适合传输已关闭应用的数据文件，不等同于支持多机并发访问的数据库共享存储。

### 19.2 新用户迁移

还没有重要数据时：

1. 创建一个空的同步目录，例如 `D:\Sync\TerminalBuddy`。
2. 打开“设置 -> 数据管理”。
3. 选择该目录并点击“应用”。
4. 重启 TerminalBuddy。
5. 创建一个测试连接，退出程序后确认同步目录中出现 `Profiles`、`ClientData` 和 `terminal_buddy.db`。

### 19.3 已有数据迁移

内置“修改数据存储路径”当前只自动复制 `Profiles`、`Workspaces`、`ClientData` 和 `Bots` 四个目录，不会复制 `terminal_buddy.db`、`debug.log` 和根目录下的旧版单文件数据。

已有数据时应采用完整迁移流程：

1. 先做完整备份。
2. 在设置页选择新目录，让程序写入新的 `dataPath`。
3. 从托盘彻底退出 TerminalBuddy。
4. 暂停同步客户端。
5. 把旧目录中尚未复制的 `terminal_buddy.db*` 和需要保留的根目录文件复制到新目录。
6. 恢复同步并等待完成。
7. 启动 TerminalBuddy，检查连接、标签、命令补全、机器人和 Web 设置。

复制数据库时必须先退出程序。若存在 `terminal_buddy.db-wal` 或 `terminal_buddy.db-shm`，应把所有 `terminal_buddy.db*` 文件作为同一组处理。

## 20. 导入、导出、完整备份与恢复

### 20.1 内置 JSON 导出不是完整备份

“设置 -> 数据管理 -> 导出全部数据”会导出：

- `Profiles`、`Workspaces`、`ClientData` 和 `Bots` 中的 JSON 文件。
- 数据目录根部存在的 `command_history.json`、`command_templates.json` 和 `settings.json`。

它不会导出：

- `terminal_buddy.db`，其中包含当前命令历史和机器人运行数据。
- `debug.log`。
- 默认 `%APPDATA%\TerminalBuddy\settings.json` 中的后端控制设置。
- Windows 凭据管理器中的 RDP 凭据副本。

所以该按钮适合导出 JSON 配置，不应作为唯一备份方式。

### 20.2 JSON 导入规则

内置导入会把备份中的同名 JSON 写入当前目录：

- 会覆盖同名文件。
- 不会先清空目录中备份未包含的其他文件。
- 不会恢复 `terminal_buddy.db`。
- 部分设置需要重启后生效。
- 旧主题数据可以被识别，但当前版本不会恢复使用。

TerminalBuddy 1.4.0 还有一个已知兼容问题：导出文件会自动增加顶层 `version` 和 `exportTime` 字段，但导入器的允许列表没有包含这两个字段，直接导入刚导出的文件会提示“导入文件包含未知数据类型”。如确实需要使用内置导入：

1. 保留原始导出文件不动。
2. 复制出一份专门用于导入的副本。
3. 用文本编辑器删除副本最外层的 `version` 和 `exportTime` 两个字段。
4. 确认 JSON 逗号和括号仍然合法。
5. 再选择这个副本导入。

导入文件本身可能包含 AI 凭据和机器人密文，应按敏感文件保管。

### 20.3 推荐的完整备份

完整备份应同时包含：

1. 当前自定义数据目录的全部内容。
2. `%APPDATA%\TerminalBuddy\settings.json`。

备份步骤：

1. 从托盘彻底退出 TerminalBuddy。
2. 确认任务管理器中没有 TerminalBuddy 进程。
3. 暂停同步客户端。
4. 复制整个数据目录，不要只挑 JSON 文件。
5. 另行复制 `%APPDATA%\TerminalBuddy\settings.json`。
6. 给备份目录标注日期和应用版本。
7. 恢复同步客户端。

可使用以下 PowerShell 模板。执行前把占位路径改成自己的目录：

```powershell
$dataSource = 'D:\Sync\TerminalBuddy'
$backupRoot = 'D:\Backups\TerminalBuddy-2026-08-17'

Copy-Item -LiteralPath $dataSource -Destination "$backupRoot\Data" -Recurse
Copy-Item -LiteralPath "$env:APPDATA\TerminalBuddy\settings.json" -Destination "$backupRoot\backend-settings.json"
```

备份包含凭据材料和命令历史，应放在受控目录并启用磁盘加密。

### 20.4 恢复

恢复到原设备、原 Windows 用户：

1. 退出 TerminalBuddy。
2. 备份当前损坏或待替换的数据目录。
3. 恢复完整数据目录。
4. 恢复后端 `settings.json`，或启动后重新选择数据目录。
5. 启动并逐项验证。

恢复到另一台设备或另一个 Windows 用户：

1. 恢复完整数据目录。
2. 在新设备的设置页重新选择该目录。
3. 重新填写 RDP 密码。
4. 重新授权机器人通道或重新填写 Secret。
5. 重新设置 Web 密码。
6. 检查 AI 用量凭据是否仍应继续使用。
7. 重新安装 Claude Code Hook。

## 21. 隐私与安全清单

在分享截图、日志、备份或配置前，至少检查：

- `Profiles/*.json` 中的主机、用户名、路径、启动命令和环境变量。
- `ClientData/settings.json` 中的 API Key、Token 和 Cookie。
- `ClientData/saved_tabs.json` 中的项目路径和会话信息。
- `ClientData/command_history.json` 或 `terminal_buddy.db` 中的历史命令。
- `Bots/*.json` 中的通道目标、用户 ID 和加密凭据。
- `debug.log` 中的路径、错误上下文和运行信息。
- Web 快速访问 URL 中的 `token` 参数。
- RDP 主机地址和 Windows 凭据管理器条目。

DPAPI 密文不是可公开发布的数据。它只能降低同一文件被直接读取的风险，不能替代访问控制和安全备份。

## 22. 常见问题

### PowerShell 7 配置启动失败

确认系统已安装 PowerShell 7，并能在普通命令窗口运行：

```powershell
pwsh --version
```

不能运行时先修复 PowerShell 7 安装或 PATH，再使用该连接类型。

### VS Code 终端模式不可选

查看“行为设置”中的检测原因。通常需要可用的系统 Node.js 和已准备好的终端插件。可以先切回“默认”，它不会影响连接和数据。

### 启动命令顺序异常

把快速结束的初始化命令放前面，把交互式长任务放最后。使用“追加参数”预设时，确认配置是否只有一条目标启动命令。

### 修改数据目录后命令历史为空

内置路径迁移没有复制 `terminal_buddy.db`。退出程序后，把旧目录的 `terminal_buddy.db*` 完整复制到新目录，再重新启动。

### 同步到新电脑后 RDP 或机器人凭据失效

这是 DPAPI 的预期行为。相关密文绑定原 Windows 用户环境，应在新设备重新输入或重新授权。

### 手机无法访问 Web 页面

依次检查：

1. Web 服务状态是否显示为已启动。
2. 手机和电脑是否处于同一局域网或 VPN。
3. Windows 防火墙是否允许该端口。
4. 端口是否被其他程序占用。
5. 自定义 Host 是否只改了显示地址，但 DNS 或反向代理尚未配置。
6. 路由器是否启用了客户端隔离。

### Web 快速链接突然失效

快速 JWT 有效期为 24 小时，且 Web 服务重启后旧 Token 会立即失效。回到设置页重新生成二维码或链接。

### 关闭窗口后 Web 或机器人仍在运行

启用了“关闭时最小化到托盘”时，窗口关闭并不代表程序退出。使用托盘菜单退出，或在 Web 设置中先停止服务。

### 导入后部分设置没有变化

先重启应用。如果仍未恢复，检查该设置是否保存在默认 `%APPDATA%\TerminalBuddy\settings.json` 或 `terminal_buddy.db` 中，这两部分不在内置 JSON 导入范围内。

### 刚导出的 JSON 无法导入

如果错误为“导入文件包含未知数据类型: version”或 `exportTime`，这是 1.4.0 的导出与导入元数据兼容问题。保留原文件，在副本中删除最外层的 `version` 和 `exportTime` 字段后重试。

## 24. 建议的日常流程

一套稳定的日常使用节奏如下：

1. 从分组连接启动项目终端。
2. 用起始路径直接进入项目目录。
3. 使用启动命令或参数预设进入所需工具模式。
4. 在文件面板打开同一项目，使用内置编辑器和 Git 工具栏。
5. 需要并行观察时切换两栏或四格分屏。
6. 离开电脑时让 Hook 和机器人处理等待通知，必要时通过 Web 查看。
7. 切换设备前彻底退出 TerminalBuddy，并等待同步完成。
8. 定期做包含数据库和后端设置的完整冷备份。

这套方式的核心是：连接配置负责“进入哪里、先做什么”，启动参数负责“本次以什么模式运行”，选项卡恢复负责“回到上次现场”，同步和备份负责“让配置可迁移但不并发写入”。
