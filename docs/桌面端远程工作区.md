# 桌面端远程工作区

Windows 客户端可在本机工作区和远程 TerminalBuddy 服务（例如飞牛 Docker）之间切换。远程模式复用完整网页的业务界面，但窗口外壳、系统通知与文件拖放仍由本机负责。

## 功能范围

- 连接远程 TerminalBuddy 的 Web API，管理远程服务的终端、项目、连接配置、命令模板、文件、Git、原生 AI 会话与定时任务。
- 支持保存多个远程连接；顶部开关直接切换本地 / 远程，远程状态下从下拉框选择服务器（选择即连接），不必逐级点按钮。
- 登录令牌由 Rust 持有并用 Windows DPAPI 加密保存到数据目录 `remote_workspace.json`，不写入 `localStorage`，也不交给页面脚本。
- 「返回本机工作区」保留登录，「断开并删除登录」清除令牌。
- 远程令牌失效时打开重新登录面板，已运行的远程终端不受影响。

## 边界

- 本功能连接的是 **TerminalBuddy 服务端**，不是 Docker Engine 的 `2375/2376` 管理接口；不提供容器、镜像、网络、卷管理。
- 远程客户端在服务端始终以 `TerminalActor::Web` 身份访问，沿用 `models/terminal_access.rs` 的权限矩阵，不会获得关闭桌面端 PC 终端的额外权限。
- 窗口最小化/最大化/关闭、全局快捷键、系统通知与资源管理器属于本机能力，始终走 Tauri；远程路径不能用本机 `ShellExecute` 打开。
- 本机文件拖入远程终端时先经桌面代理上传到远程服务，再把服务器路径写入终端；远程文件下载由 Windows 保存对话框选择落点。
- 单窗口；切换工作区通过整页重载隔离本机与远程状态，避免终端 ID、页签与设置串线。重载不会终止本机 Rust 进程，回到本机时按后端存活终端直接接回原会话，不会重复创建 PTY。

## 数据流

```text
React 业务层
  ├─ 本机工作区：invoke → Tauri 命令 → 本机 Rust 服务
  └─ 远程工作区：invoke → 主页面的 fetch/WebSocket
                    → 127.0.0.1:<随机端口> 回环代理
                    → 远程 TerminalBuddy Web API（注入 JWT）
```

回环代理只绑定 `127.0.0.1`，CORS 只接受本机 WebView 来源。远程服务若是 HTTPS，代理会在本机与远程之间完成 TLS；页面自身始终使用 HTTP 回环地址，避免证书匹配 `127.0.0.1` 失败。

## 主要代码

| 位置 | 作用 |
| --- | --- |
| `src-tauri/src/services/remote_workspace_service.rs` | 连接配置、DPAPI 令牌、回环 HTTP/WS 代理、上传与下载 |
| `src-tauri/src/commands/remote_workspace.rs` | 连接、重登、激活、切换本机、断开与文件传输命令 |
| `src/services/remoteWorkspace/` | 工作区配置、请求/事件/窗口/终端分流、本机能力桥接 |
| `src/components/remote/` | 工作区连接、重新登录与启动加载界面 |
| `src/services/platform.ts` | `isWebBackend()` 区分「业务来自 Web API」与「运行在浏览器」 |
| `src-tauri/src/web/handlers/desktop_dispatch.rs` | 远程与浏览器共用的 White-list 业务命令（显式 Web 身份） |

## 验证建议

改动后按项目规范执行：`npx tsc --noEmit`、`cargo check`、`cargo test --lib`、`python scripts/check-invoke-coverage.py`。连接真实远程服务时重点验证：登录与重登、令牌过期、断线重连、终端输入/尺寸/关闭权限、文件上传下载以及本机窗口按钮。
