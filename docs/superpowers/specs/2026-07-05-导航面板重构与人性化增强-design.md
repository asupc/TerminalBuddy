# 导航面板重构与人性化增强

- 日期：2026-07-05
- 范围：`terminal-buddy/` 前端三个导航面板（配置 / 选项卡 / 文件）+ 少量后端设置字段
- 关联：延续近期「标签导航右键菜单」「Profile 置顶」等迭代

## 1. 背景与目标

应用有三个导航型侧栏面板，当前存在两类问题：

1. **命名不一致**：可见标题已统一为「X导航」，但内部代码命名五花八门（`ConfigPanel` / `TabSidebar` / `FileTree`），且与可见名称对不上；菜单措辞中「连接」与「配置」混用。
2. **右键菜单缺项**：配置面板右键单个配置无「添加」入口、无「打开/复制启动路径」；选项卡面板右键标签无「打开目录」「复制配置信息」等便捷操作；面板宽度不持久化；终端运行时长不可见；配置不能拖拽到选项卡快速启动。

本设计完成一次性收敛：统一命名规则、补齐对称的右键操作、增加若干人性化增强。命名重构为纯机械改动（行为零变化），其余为新增能力。

## 2. 命名重构

### 2.1 可见标题

`panel-title` 文本统一为名词、去掉冗余的「导航」二字：

| 现在 | 新值 |
|---|---|
| 连接导航 | **配置** |
| 标签导航 | **选项卡** |
| 文件导航 | **文件** |

理由：
- 「导航」仅对文件面板语义成立（真在浏览目录、有前进/后退）；配置面板是「挑配置启动」、选项卡面板是「切换已打开会话」，称为"导航"用词不准。
- 更省空间，给标题栏的计数徽章与操作按钮让位。
- 「选项卡」是 Windows 系统 UI 对 tabs 的标准术语，零歧义（不会被理解成 label/tag），并与顶部横向 `TerminalTabBar` 概念对齐。

### 2.2 内部标识符

统一规则：**`<概念>Nav`** —— 组件名、文件名、根 CSS 类、CSS 子类前缀全部遵循。

| 现在 | 组件 | 文件 | 根 CSS 类 | CSS 子类前缀 |
|---|---|---|---|---|
| `ConfigPanel` | `ConfigNav` | `ConfigNav.tsx` | `.config-nav` | `.config-*` → `.config-nav-*` |
| `TabSidebar` | `TabNav` | `TabNav.tsx` | `.tab-nav` | `.tab-sidebar-*` → `.tab-nav-*` |
| `FileTree` | `FileNav` | `FileNav.tsx` | `.file-nav` | `.file-tree-*` → `.file-nav-*` |

涉及文件：
- `src/components/ConfigPanel.tsx` → `ConfigNav.tsx`（含 `ConfigNav.css`，CSS 类全量改名）
- `src/components/TabSidebar.tsx` → `TabNav.tsx`（含 `TabSidebar.css` → `TabNav.css`，CSS 类全量改名）
- `src/components/FileTree.tsx` → `FileNav.tsx`（CSS 类全量改名）
- `src/App.tsx`：更新 import 与 JSX 标签
- `RemoteFileTree.tsx` 内部仍按「远程文件树」语义保留组件名（它是 `FileNav` 在 SSH 会话下的子视图，不在本次重命名范围）

约束：
- `Profile` / `TerminalSession` 等数据模型名词不改，避免波及后端。
- 回调 prop 名（`onStartTerminal` / `onAddProfile` / `onNavigate` 等）保持不变，只改组件/类名。

### 2.3 菜单措辞统一

凡面向用户的「连接」字样统一改为「配置」，与新面板标题一致：

- 配置面板 - 分组右键：「添加连接」→ **「添加配置」**（「添加子分组」「重命名分组」不变）
- 配置面板 - 单配置右键：新增项命名均用「配置」（见 §3）
- 其它已有菜单项（如选项卡右键的「以此配置新建终端」）已用「配置」，保持不变。

## 3. 新增右键菜单项

### 3.1 配置面板 - 单个配置右键

在现有「启动 / 启动[预设] / 命令行 / 编辑 / 置顶 / 复制 / 重命名 / 删除」基础上，于「命令行」附近新增：

| 项 | 显示条件 | 动作 |
|---|---|---|
| 添加配置 | 始终显示 | `onAddProfile(profile.group \|\| '默认')` —— 默认归入该配置所在分组 |
| 打开目录 | 本地类型 + `startupPath` 非空 | `openInExplorer(profile.startupPath)` |
| 复制启动路径 | 本地类型 + `startupPath` 非空 | `navigator.clipboard.writeText(profile.startupPath)` |

> 满足「需求 2」：右键单个配置也能添加新配置，默认同分组。`onAddProfile(group)` 已支持接收分组参数，无需改签名。

### 3.2 配置面板 - 分组右键

仅措辞调整：「添加连接」→「添加配置」。其余不变。

### 3.3 选项卡面板 - 标签右键

在现有「重命名 / 以此配置新建终端 / 关闭 / 关闭其它」基础上，于「以此配置新建终端」附近新增：

| 项 | 显示条件 | 动作 |
|---|---|---|
| 打开目录 | 本地 powershell/cmd + 对应 profile `startupPath` 非空 | `openInExplorer(profile.startupPath)` |
| 复制配置名 | 终端会话（`sessionType !== 'editor'`） | `clipboard.writeText(session.profileName)` |
| 复制启动路径 | 本地类型 + `startupPath` 非空 | `clipboard.writeText(profile.startupPath)` |

> 满足「需求 3」：选项卡右键新增「打开目录」，通过资源管理器打开连接配置的 `startupPath`。

### 3.4 公共判定

- **本地类型**：`profile.terminalType === 'powershell' || profile.terminalType === 'cmd'`
- **路径非空**：`profile.startupPath && profile.startupPath.trim() !== ''`
- 复用现有后端命令 `open_in_explorer`（已支持目录直接打开 / 文件 `/select` / 不存在时回退父目录），无需新增后端命令。

## 4. 面板宽度持久化（增强 A）

`TabNav`（原 `TabSidebar`）已通过 `tab_sidebar_width` 持久化。`ConfigNav` 与 `FileNav` 当前面板宽度仅存组件内 `useState`，重启即丢失。补齐：

**后端**（`src-tauri`）：
- `AppSettings` 新增 `config_nav_width: Option<f64>`、`file_nav_width: Option<f64>`（镜像 `tab_sidebar_width`）
- 新增命令 `save_config_nav_width(width)` 与 `save_file_nav_width(width)`（镜像 `save_tab_sidebar_width`）
- 序列化保持 `camelCase`：`configNavWidth` / `fileNavWidth`

**前端**：
- `services/tauri.ts` 增加对应 wrapper
- `ConfigNav` / `FileNav` 的宽度 state 改为：mount 时 `getBackendAppSettings()` 读取、`onResizeEnd` 时调用对应 save 命令；模式与 `TabNav` 完全一致。

## 5. 终端运行时长显示（增强 G）

**数据模型**：`TerminalSession` 新增 `createdAt: number`：
- `addSession(session)` 时若未提供则填 `Date.now()`
- 旧 tab 从 `localStorage` 恢复时若无该字段，加载时补 `Date.now()`（视为"刚打开"）
- 该字段不参与 `saveTabsToStorage` 的关键身份判定，向后兼容

**显示**：
- 仅终端会话（`sessionType !== 'editor'`）显示，编辑器不显示
- `TabNav` 叶子项标签名后追加淡色后缀：`my-server · 5m`
- 格式（新建 `src/utils/formatDuration.ts`）：
  - `< 60s` → `Xs`
  - `< 60m` → `Xm`
  - `< 24h` → `Xh`
  - 否则 → `Xd`
- 刷新：组件内 `setInterval(60_000)` 触发一个 `tick` state 强制重渲染（复用现有 `settingsTick` 模式），卸载时清理。

## 6. 配置面板 → 选项卡面板 拖拽（增强 H）

**store**：`appStore` 新增 `dragProfileId: string | null` 与 `setDragProfileId`（与现有 `dragPaths` 平行，互不干扰）。

**ConfigNav**：
- 单配置叶子项 `onDragStart` → `setDragProfileId(profile.id)`，`e.dataTransfer.effectAllowed = 'copy'`
- `onDragEnd` → `setDragProfileId(null)`（清理可能的取消拖拽）

**TabNav**：
- 整个 `.tab-nav-content` 区域作为放置目标
- `onDragOver`：当 `dragProfileId` 非空时 `e.preventDefault()` 并切换到高亮样式（CSS 类如 `.tab-nav-drop-target`）
- `onDrop`：读 `dragProfileId` → 在 `profiles` 中查到 → 调用 `onStartTerminal(profile)` → `setDragProfileId(null)`
- 仅认 `dragProfileId`；文件拖拽（`dragPaths`）不在 TabNav 处理，保持现有 `TerminalInstance` 接收逻辑不变，无冲突。

## 7. 数据模型与后端变更汇总

```diff
// src/types/index.ts
export interface TerminalSession {
  ...
+ createdAt?: number;   // 启动时间戳；addSession 时填 Date.now()
}

// src-tauri AppSettings
pub struct AppSettings {
  ...
  pub tab_sidebar_width: Option<f64>,
+ pub config_nav_width: Option<f64>,
+ pub file_nav_width: Option<f64>,
  ...
}
```

新增前端 wrapper：`saveConfigNavWidth` / `saveFileNavWidth`（`services/tauri.ts`）。
新增后端命令：`save_config_nav_width` / `save_file_nav_width`（注册到 `invoke_handler!`）。

## 8. 实施顺序建议

为降低回归风险，建议按以下顺序、每步可独立验证：

1. **命名重构（§2）**：先完成纯重命名，单独跑一遍回归（启动/搜索/排序/分组/F2 重命名/拖拽文件/分屏）。CSS 类全量改名建议用脚本化查找替换 + 人工核对。
2. **后端设置字段（§4、§7）**：加 `configNavWidth` / `fileNavWidth` 与 save 命令。
3. **宽度持久化接入（§4）**：`ConfigNav` / `FileNav` 接上新字段。
4. **运行时长（§5）**：加 `createdAt` + 工具函数 + TabNav 显示。
5. **右键菜单新增项（§3）**：配置面板三项、选项卡面板三项、分组右键措辞。
6. **拖拽（§6）**：store 字段 + ConfigNav 拖出 + TabNav 放入。
