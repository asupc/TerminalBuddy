# TerminalBuddy 机器人通知接入指南

TerminalBuddy 当前支持以下通道：

| 通道 | 文字 | 终端截图 | 引用回复回写终端 |
|---|---|---|---|
| 飞书应用机器人 | 支持 | 支持 | 支持 |
| 企业微信群机器人 | 支持 | 支持 | 不支持，群 Webhook 无入站事件 |
| DingTalk 群机器人 | 支持 | 不支持本地图片 | 不支持，群 Webhook 无入站事件 |
| QQ 机器人桥接 | 由桥接端实现 | 由桥接端实现 | 支持 |
| 通用机器人桥接 | 由桥接端实现 | 由桥接端实现 | 支持 |

机器人配置位于“设置 -> 机器人通知”。平台凭据由 Rust 后端使用 Windows DPAPI 加密，设置页不会回显已有 Secret。

## 飞书应用机器人

### 1. 创建应用

1. 打开[飞书开放平台](https://open.feishu.cn/app)，创建企业自建应用。
2. 启用“机器人”能力。
3. 在权限管理中至少开通发送消息、读取用户发给机器人的消息、上传图片所需权限。
4. 发布应用，并把机器人加入接收通知的群聊。

### 2. TerminalBuddy 配置

新增“飞书应用机器人”通道并填写：

- `App ID`、`App Secret`：应用凭据；
- `接收 ID 类型`：双向群聊建议固定为 `chat_id`；
- `目标会话 ID`：飞书群的 `chat_id`；
- `回调验证 Token`：与飞书事件订阅页面配置一致；
- `允许回复的用户 ID`：允许向终端写入回复的用户 `open_id`，默认空名单会拒绝所有回复。

保存后点击纸飞机按钮发送测试消息。

### 3. 配置事件回调

设置页会显示本机回调地址：

```text
http://<电脑局域网IP>:<Web API 端口>/api/bot/feishu/events
```

飞书要求公网可访问的 HTTPS 地址。使用反向代理或隧道把公网 HTTPS URL 转发到上述本机地址，再在飞书事件订阅中：

1. 填写公网回调 URL；
2. 填写与 TerminalBuddy 相同的 Verification Token；
3. 订阅 `im.message.receive_v1`；
4. 保存并重新发布应用。

当前内置实现使用飞书 HTTP 事件回调，不使用官方 SDK 的 WebSocket 长连接，因此双向回复需要公网入口。只发送通知时无需配置回调。

### 4. 回复决策

必须引用机器人发送的“等待确认”或“等待回答”文字消息后回复。TerminalBuddy 会依次校验：

- 回调 Token；
- 群 `chat_id`；
- 回复用户 `open_id` 白名单；
- 被引用的飞书 `message_id`；
- 决策是否仍为待处理状态；
- 原终端是否仍存在。

校验通过后，回复正文会写入对应 PTY，并根据设置追加一次回车。飞书会收到“已发送到终端”的回执。同一决策只接受第一条回复。

## 企业微信群机器人

在企业微信群中添加群机器人，复制 Webhook URL，新增“企业微信群机器人”通道并粘贴 URL。

该通道支持文字和 PNG 终端截图。群机器人 Webhook 本身不能接收入站消息，因此不支持引用回复。需要双向能力时应使用企业微信自建应用或通用桥接通道。

## DingTalk 群机器人

在 DingTalk 群中添加自定义机器人，选择加签安全方式，复制 Webhook URL 和签名 Secret。

该通道直接发送文字通知并支持签名。DingTalk 群 Webhook 不能上传本机 PNG，也不能接收引用回复；需要截图和远程决策时使用 DingTalk Stream 桥接到“通用机器人桥接”通道。

## QQ 与通用桥接

QQ Gateway、个人微信以及需要长连接的 DingTalk 可由 OpenClaw、Hermes 或独立服务承接。TerminalBuddy 向“桥接发送 URL”发送：

```json
{
  "eventId": "uuid",
  "decisionId": "uuid-or-null",
  "platform": "qq",
  "targetId": "group-or-user-id",
  "terminalId": "terminal-id",
  "terminalName": "生产环境",
  "kind": "question",
  "text": "通知正文",
  "screenshotBase64": "data:image/png;base64,...",
  "callbackChannelId": "channel-uuid"
}
```

配置了“发送鉴权 Token”时，请求携带：

```text
Authorization: Bearer <发送鉴权 Token>
```

桥接端响应：

```json
{
  "success": true,
  "messageId": "平台消息 ID",
  "screenshotSent": true
}
```

只有返回 `messageId` 才会建立远程决策绑定。

收到用户引用回复后，桥接端调用设置页显示的回调地址：

```text
POST http://<电脑IP>:<端口>/api/bot/inbound/<channelId>
Authorization: Bearer <回调验证 Token>
Content-Type: application/json
```

```json
{
  "senderId": "user-id",
  "conversationId": "group-or-user-id",
  "messageId": "new-user-message-id",
  "replyToMessageId": "quoted-bot-message-id",
  "text": "用户回复"
}
```

成功响应：

```json
{
  "success": true,
  "message": "已发送到终端：生产环境"
}
```

桥接端必须保留平台原始 `messageId` 和引用关系。禁止用“最近一个通知”推测目标终端。

## 安全建议

- 只把个人或受控群聊加入通知目标。
- “允许回复的用户 ID”使用最小白名单，空名单默认拒绝。
- 回调服务暴露到公网时必须使用 HTTPS、反向代理访问控制和随机高强度 Token。
- 不要在代理日志中记录请求正文，正文可能含终端截图和业务数据。
- 不需要远程决策时，关闭“发送决策通知”或使用单向 Webhook 通道。
