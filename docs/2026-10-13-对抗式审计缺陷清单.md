## P0

### [ ] TB2-P0-01 消除 Web 服务关停时的 `Arc::into_inner` panic

**目标**

停止或重启 Web API 时，只要存在任何未结束的连接，进程不得 panic；release 构建不得因此终止。

**涉及文件**

- `src-tauri/src/web/server.rs`
- `src-tauri/src/commands/web.rs`

**根因**

`web/server.rs:337-340` 在 accept 循环退出后执行：

```rust
std::sync::Arc::into_inner(graceful)
    .expect("accept 循环结束后不应再有连接 task 持有引用")
    .shutdown()
    .await;
```

每个连接任务都克隆一份 `Arc<GracefulShutdown>`（`web/server.rs:306`）并以其调用
`graceful.watcher().watch(conn)`（`web/server.rs:322`），该 watcher 会持有 receiver 直到连接结束。
因此只要有任一连接仍存活，`Arc::into_inner` 返回 `Err`，`expect` 触发 panic。
`src-tauri/Cargo.toml:70` 的 `[profile.release] panic = "abort"` 会把该 panic 变成进程直接终止，
从而绕过 `commands/window.rs:55-63` `window_exit_app` 中的 `shutdown_all_terminals` /
`release_all_on_shutdown` 收尾路径。

**必须完成**

- [ ] 移除 `Arc::into_inner(...).expect(...)` 这一模式，改为持有独立可触发的 shutdown 句柄。
- [ ] 连接任务只持有 `watcher()`（不可触发关停），触发侧保留唯一 `GracefulShutdown` 所有权。
- [ ] accept 循环退出后，必须先完成在途连接排空再返回，且排空过程有明确上界，不得无限等待。
- [ ] 关停路径不得依赖 panic 或 `abort` 完成资源回收。
- [ ] 验证 `restart_web_server` 与设置页「停止 Web 服务」两条路径均能正常返回并记录日志。

**验收标准**

| 关停时连接状态 | 预期 |
| --- | --- |
| 无连接 | 正常关停，打印「服务器已停止」 |
| 存在已建立但未发送请求头的 TCP 连接 | 正常关停，不 panic |
| 存在 keep-alive 空闲连接 | 正常关停，不 panic |
| 存在活跃 WebSocket | 正常关停，不 panic；订阅由终端关闭流程各自收尾 |

- [ ] 新增针对「关停时仍有连接」的 Rust 测试或集成测试，覆盖上表全部场景。
- [ ] 确认 release 构建下上述场景不再产生进程终止。

**补充问题（同一任务内一并修复）**

`commands/web.rs:47-59` 的 `restart_web_server` 在 `start_http_server` 之后无条件返回
`Ok("HTTP 服务已启动，端口: ...")`；而 `web/server.rs:273-278` 在端口 bind 失败时只打印日志并
`return`，不回传错误。因此端口被占用时，前端会显示启动成功但服务实际不可用。

- [ ] `restart_web_server` 必须能反映真实启动结果（例如等待 bind 结果回执后再返回）。
- [ ] bind 失败时返回中文错误，并说明端口占用等可执行处理建议。

### [ ] TB2-P0-02 项目作用域改为规范化路径比较

**目标**

Web 文件树与 Git 接口只能访问已登记项目目录的真实子树；任何 `..`、链接或等价路径表示都不得越界。

**涉及文件**

- `src-tauri/src/web/handlers/mod.rs`
- `src-tauri/src/web/handlers/fs_handler.rs`
- `src-tauri/src/web/handlers/git_handler.rs`

**根因**

`web/handlers/mod.rs:37-41` 的作用域键规范化只做四件事：去首尾空白、反斜杠转正斜杠、去尾分隔符、
转小写。它 **不解析 `..`、不做 `canonicalize`、不处理 junction 与符号链接**。
判定逻辑 `handlers/mod.rs:24-27` 仅做字符串前缀比较：

```rust
let base = normalize_scope_key(&project.path);
!base.is_empty() && (key == base || key.starts_with(&format!("{}/", base)))
```

由于 `..` 原样保留在键中，任何「以某登记项目为前缀 + 若干 `..` 」的路径都会通过检查。
下游随后把**原始请求路径**（含 `..`，文件系统与 git 会自行解析）直接用于真实操作：
`fs_handler.rs:34-38` 丢弃返回值、把 `q.path` 交给 `list_directory`；
`git_handler.rs:112/127`（status / branches）同样把 `q.repo` 原样传入 git 命令族；
`git_handler.rs:63`（start_operation）则把返回的规范化键用作互斥键（关联 `TB2-P2-02`）。

**必须完成**

- [ ] 作用域判定改为先 `canonicalize` 再按路径组件比较，不使用字符串前缀。
- [ ] 输入路径包含父目录组件（`..`）时明确拒绝。
- [ ] 比较必须能正确处理 Windows 的大小写不敏感语义与 UNC / 盘符形式。
- [ ] 已登记项目自身不存在或不可解析时应拒绝，而不是回退为字符串比较。
- [ ] `ensure_project_scope` 返回的应当是规范化后的真实路径，供下游直接使用。
- [ ] 明确决定是否阻断符号链接 / junction 越界；若阻断，须在同一任务内实现并测试。

**验收标准**

| 请求路径 | 预期 |
| --- | --- |
| 登记项目根目录 | 允许 |
| 登记项目的真实子目录 | 允许 |
| 登记项目内 `./sub` 等价写法 | 允许，且解析为同一路径 |
| `<登记项目>\..\..\<未登记目录>` | 拒绝 |
| `<登记项目>\..\<同前缀伪造目录>` | 拒绝 |
| 指向项目外部的目录链接 | 按本任务决策执行，且行为有测试覆盖 |

- [ ] 新增 Rust 单元测试覆盖上表全部场景。
- [ ] 在真实未登记目录上验证 `/api/fs/list` 与 `/api/git/status` 均返回 403。

### [ ] TB2-P2-02 Git 互斥键改用真实仓库根

**根因**

`web/handlers/git_handler.rs:63` 使用 `ensure_project_scope(&repo)` 的返回值作为操作表键：

该键是**请求路径**的规范化字符串，而非真实仓库根。由于 `TB2-P0-02` 中描述的同一路径可用多种

- [ ] 非 Git 目录、仓库解析失败的场景要返回明确错误，不得回退为请求路径作为键。
- [ ] 操作记录表需考虑长期增长（清理已完成记录或设定上限）。

**验收标准**

- [ ] 对同一仓库用不同路径写法并发发起两个 Git 操作，第二个返回 409。
