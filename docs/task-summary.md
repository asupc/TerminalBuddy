# 窗口任务摘要

桌面版在「设置 → 外观设置」中开启「显示任务摘要」，手机版在设置页开启同名选项。开关保存在后端 `settings.json` 的 `showTaskSummary` 字段，缺省为 `false`，桌面、完整网页和手机版共用。

开启后，终端标签、侧栏、分屏标题、手机会话列表和活动窗口标题使用「任务摘要 · 原名称」。原名称仍用于重命名和恢复标签；关闭开关立即恢复原名称。未找到摘要时继续显示原名称。各端每 4 秒获取最新摘要和开关状态，关闭时后端只返回设置状态，不扫描会话文件。

摘要复用会话历史的解析规则。Claude 优先采用应用内重命名、官方会话标题或摘要，之后使用首条提问；Codex 优先采用应用内重命名、线程名称，之后使用会话元数据中的标题或首条实际用户任务。文本会合并空白并截短，不额外请求模型生成摘要。

## 当前会话的关联

- Claude：现有的已认证 Hook 提供当前会话 ID；终端进程树和 `CLAUDE_CONFIG_DIR/sessions/<pid>.json` 作为发现路径。支持单独设置的 Claude 配置目录。
- Codex：应用启动 CLI 时仅为本次进程指定独立的 `log_dir`，从 `codex-tui.log` 的外层 `session_loop` span 取得 `thread_id`。`CODEX_HOME`、认证和会话历史的保存位置保持一致；显式 `resume` 的会话 ID 可直接关联。
- Codex 后备路径：CLI 日志格式变化或在 Shell 中手动启动时，从终端的 Codex 子进程实际打开的 rollout 文件取得会话 ID。Linux 读取 `/proc/<pid>/fd`；Windows 通过 Restart Manager 查询文件占用进程，只执行查询。排除子代理会话；归属有歧义时保留原名称。

所有路径都使用确切的会话 ID。不会将同一项目目录下最新修改的历史记录直接认作当前任务。Web 的批量查询按现有终端访问权限矩阵校验每个终端 ID。

会话文件只在变更后重新提取标题，读取量有上限；同一个 Codex 配置目录的进程文件和线程名称在每轮查询中共用。终端退出后清除内存关联，并在进程结束后删除本次 Codex 的临时日志目录。
