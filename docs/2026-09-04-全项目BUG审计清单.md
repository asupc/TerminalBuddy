## 1. 使用规则

1. 原始条目编号 1–41 仅用于追溯；实际实施以本文件中的 `TB-*` 任务编号为准。
2. 只有“实施任务”章节中的任务可以直接进入开发。
3. “待产品决策”条目必须先确认行为预期，不得自行扩大实现范围。
4. “排除项”已被当前代码反证；除非出现新的稳定复现，不再按 BUG 修复。
5. 实施时以符号和调用链定位代码，不依赖原审计中的旧行号。
6. P0/P1 任务应拆分提交，避免与无关重构混在同一个改动中。
7. 新增 Rust↔TypeScript 字段时继续使用 `camelCase`；新增 Tauri 命令时必须同步 `commands/mod.rs` 和 `lib.rs` 注册。
8. 除明确写出仓库根文件（如 `CLAUDE.md`）外，本文代码路径均相对于 `terminal-buddy/`。

### 2.3 新增发现

原清单遗漏了一个高优先级生命周期问题：

- PTY 自然退出时只把实例标记为 `exited`，没有从 `TerminalService.instances` 删除，也没有执行统一 backend cleanup。
- 因此自然退出不仅泄漏 SSH session，还会长期保留隐藏的 `TerminalInstance`、PTY master/writer/child handle 和输出缓冲。
- 本问题已合并进 `TB-P0-03`。

### 2.4 Tauri 命令边界复核

更完整的语法扫描结果：

- Tauri 注册命令：126 个，全部唯一。
- 桌面前端 `invoke()`：115 个调用点、114 个唯一命令。
- 前端调用但后端未注册：0 个。
- 注册但无桌面 `invoke()`：12 个。

原清单“不存在 command not found 风险”的结论成立，但“111 个 invoke”计数不准确。

`list_terminals` 和 `peek_terminal_output` 的底层 service 方法被 Web 层使用，但对应的 **Tauri command wrapper** 仍没有桌面调用，不能据此排除为冗余注册。

- [x] 非共享模式下，Web 的终端列表不得返回 PC-owned terminal。
- [x] 非共享模式下，对 PC terminal 的终端 WS 握手必须在 upgrade/subscribe/peek history 前返回 403。
- [x] 共享模式下，允许 Web 查看、订阅、输入和 resize PC terminal。

**实施记录（2026-09-06）**

- 新增 `src-tauri/src/models/terminal_access.rs`（纯策略 + 单元测试），在 `models/mod.rs` 注册：
  - `TerminalActor`（Pc / Web）、`TerminalAction`（View / Input / Resize / RenameMetadata /
    Close）、`is_terminal_action_allowed(actor, owner, action, share_sessions)`。同侧归属直接
    放行；Web→PC 的 Close **永远**拒绝（接管 ≠ 关闭），其余跟随共享开关；Pc→Web 的 View
    始终放行（桌面只读查看是既有产品合同），写操作跟随共享开关。

  `SettingsService::share_sessions_enabled()`，因此运行中关闭共享后下一次操作立即被拒。

  `acknowledge_terminal_output` / `drain_terminal_output` / `peek_terminal_output` /
  `terminal_loading_mode` / `close_terminal` 全部改为接收 `actor` 并先走 `authorize`。
- 列表过滤与直连拦截同源：`list_terminals_info_for(actor)` 用同一个

  调用它；即使手机端已知 terminal id，`terminal_ws_handler` 也会在 `ws.on_upgrade`、

  `NotFound → 404`、`Denied → 403`。
- 连接存续期的授权撤销：`handle_terminal_socket` 外层 select 里加了

  授权时走 `SocketExit::Unauthorized`：先 abort 输入任务，再把中文原因冲刷给手机端，最后收尾。
  输入 / resize 另有逐消息复核（`write_to_terminal` / `resize_terminal` 内部授权）。
- Web DELETE 走 `TerminalService::close_terminal(TerminalActor::Web, WebClose)`，PC 终端在两种
  共享模式下都返回 403 并给出「请在桌面端关闭该标签页」。
- 文档同步：`CLAUDE.md`、`AGENTS.md`、`docs/完整使用与配置指南.md`、
  `docs/specs/2026-07-06--mobile-web-access.md` 的权限矩阵改为与 `terminal_access.rs` 一致。
- 单元测试 7 个（`models::terminal_access::tests`），按「actor × owner × 5 种 action × 共享开关」

- 待人工回归：PC/Web 两端 UI 的「只读」「接管中」「断开接管」状态一致性需要桌面 GUI +

### [x] TB-P0-02 终端创建事务化与失败回滚

**目标**

任何创建失败都不得留下进程、实例、reader、hook token 或伪会话。

**涉及文件**

- `src-tauri/src/commands/terminal.rs`
- `src-tauri/src/services/claude_hook_service.rs`

**必须完成**

- [x] 将 `build_init_commands`、`resolve_pwsh_exe` 等可提前执行的失败步骤移到 backend spawn 和 `insert_instance` 之前。
- [x] 为 spawn 后、创建完成前的资源建立 RAII/rollback guard；只有 `finalize_terminal_creation` 成功后才 commit。
- [x] rollback 至少覆盖：关闭 backend、丢弃 reader、从实例表删除、注销 Claude hook token、避免发送 created/session-changed 成功事件。
- [x] `create_terminal` 与 `create_blank_terminal` 共用同一套创建事务，不保留两份不同的清理逻辑。
- [x] 创建失败日志必须包含 terminal id、terminal type 和失败阶段，但不得记录凭据/token。

**验收标准**

- [ ] 在未安装 PowerShell 7 的环境启动 `pwsh` profile/blank terminal，命令返回可读错误。
- [ ] 失败后 `instances` 不含该 id，hook token 表不含该 id，系统中无残留 `cmd.exe`/PTY child。
- [ ] 连续失败 20 次，实例数、handle 数和 hook token 数不持续增长。
- [ ] 正常 cmd/PowerShell/SSH/Docker/K8s 创建路径不回归。

**实施记录（2026-09-06）**

- 新增 `TerminalCreation` RAII 事务守卫（`commands/terminal.rs`），字段
  `{terminal_id, terminal_type, instances, app, stage, hook_registered, backend, reader,
  inserted, committed}`。`create_terminal` 与 `create_blank_terminal` 都只走这一个守卫，
  不再各自维护清理分支。
- 失败前置：`build_init_commands`、`resolve_pwsh_exe`、profile 解析与参数校验全部在
  backend spawn 之前完成，可提前失败的路径根本不产生进程。
- `Drop for TerminalCreation` 在未 `commit()` 时按逆序回滚：从 `instances` 移除 → 注销
  Claude hook token → 丢弃 reader → 走 `release_terminal_resources(..., StartupRollback)`
  关闭 backend（阻塞 close 放在 `spawn_blocking`）；回滚路径不发送 created /
  session-changed 事件，前端不会看到伪会话。
- `stage` 字段随创建推进逐段更新，`fail()` 输出
  `[create] FAILED, id=…, type=…, stage=…, error=…`，代码注释写明「不得写入 env、token 或
  凭据」；env / SSH 密码 / hook token 均不进日志。

### [ ] TB-D-03 JWT 存储与 WebSocket 传输架构（原 23）

**已确认风险**

- terminal/meta WS 在 query 中发送 JWT。
- Zustand persist 将 JWT 保存到 localStorage，任意同源 XSS 可读取。
- 快速访问 URL 初始请求携带 JWT，但 Web App 会立即 `history.replaceState` 清除地址栏 query。
- 后端 `decode` 会校验签名、算法和 exp；当前未绑定 issuer/audience。

**推荐长期方案**

- 登录成功后改用 `HttpOnly`、`SameSite=Strict` cookie；
- 快速访问二维码携带短时、一次性兑换码，而不是 24 小时 bearer JWT；
- WebSocket 使用同源 cookie 完成握手；
- 如果继续用 bearer token，则使用短时一次性 WS ticket，避免长期 JWT 出现在 WS URL。

**决策前必须明确**

- 局域网纯 HTTP 是否继续支持；
- 是否引入 HTTPS/自签证书；
- token 失效和多设备注销模型；
- 快速访问链接的有效期和一次性语义。

`TB-P2-07` 的认证过期 UX 不依赖本架构决策，可先实施。

## 7. 风险记录

### TB-R-01 Claude hook token 被终端子进程继承（原 36）

**现状与信任边界**

- token 按 terminal 注册，通过环境变量传给该终端及后代进程。
- 同一终端中的任意进程都可读取 token，并以该 terminal 身份提交 hook 请求。
- 服务只监听 localhost，攻击者仍需处于同一 Windows 用户/终端执行信任域。

**当前处置**：接受为设计权衡，不列入本轮缺陷修复。

**后续触发条件**：如果未来允许不受信任程序、插件或多用户进程共享同一终端，应升级为短时、事件级、可轮换凭据，并缩小 hook endpoint 能力。

## 8. 排除项：不进入实施

### TB-X-01 Web 终端以 0×0 打开（原 6）

后端 `resolve_terminal_size` 在创建 backend 前把 0 回退为 24×80。Web 发送 0 是“使用后端默认值”的现有协议，不会把 0×0 传给 ConPTY。

### TB-X-02 Web 接管后按陈旧 PC 尺寸恢复（原 10）

接管结束监听器会清空 takeover 尺寸状态，执行强制 fit，并以 redeclare 方式重新下发当前桌面尺寸。原清单描述的恢复链路不成立。

### TB-X-03 300ms 延迟导致命令写进未就绪 shell（原 29）

固定延时可以改进，但 PTY 输入会排队等待 shell 读取。没有稳定复现前，不按数据丢失/命令错投 BUG 实施。

### TB-X-04 EOF 丢失完整 UTF-8 字符（原 30）

EOF 时留下的 pending bytes 无法构成完整 UTF-8 字符。可选输出 replacement character，但不能恢复不存在的完整字符。

### TB-X-05 dispose 后 ref 未清空（原 31）

当前代码已经连续执行：

```ts
xtermRef.current?.dispose();
xtermRef.current = null;
fitAddonRef.current = null;
```

### TB-X-06 WNDPROC 指针宽度/链式调用错误（原 35）

当前使用的是 Windows 指针宽度 API；旧 WNDPROC 被保存并通过 `CallWindowProcW` 调用，是标准子类化链。`transmute` 属 unsafe 封装问题，但现有证据不足以认定运行时缺陷。

可独立考虑的小改进：检查 `SetWindowLongPtrW` 返回值和 `GetLastError`，但不得沿用原条目的错误理由。
