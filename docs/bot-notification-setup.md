# 机器人通知配置帮助

TerminalBuddy 可在 Claude Code 需要决策或任务完成时，通过机器人主动推送通知到手机，部分平台支持直接回复决策。

## 支持的平台

| 平台 | 配置方式 | 通知形式 | 双向回复 |
|------|---------|---------|---------|
| 飞书 | 扫码 | 应用机器人私聊 | ✅ 支持 |
| 钉钉 | 扫码 | 应用机器人单聊 | 暂不支持（仅推送） |
| QQ | 手动桥接 | 经桥接服务中转 | ✅ 支持 |
| 通用桥接 | 手动桥接 | 经桥接服务中转 | ✅ 支持 |

> 企业微信暂未提供（其机器人需 WebSocket 长连接，后续迭代再支持）。

---

## 飞书（扫码配置）

1. 在「设置 → 机器人通知」新增或展开一个**飞书**通道，点击「**扫码配置**」。
2. 用飞书 App 扫描弹窗中的二维码，按提示授权。
3. 授权成功后，**App ID、App Secret 与接收目标（你的 open_id）自动填入并保存**。
4. 点「发送测试消息」验证。

**原理**：扫码走飞书设备码授权（`accounts.feishu.cn`），自动创建一个个人应用机器人并获取凭证，无需手动到开发者后台创建应用。

---

## 钉钉（扫码配置）

1. 展开一个**钉钉**通道，点击「**扫码配置**」。
2. 用钉钉 App 扫描二维码授权。
3. **AppKey、AppSecret 自动填入并保存**。
4. **手动填写「收件人 userId」**（见下方获取方式）。
5. 点击「**保存**」，再点「发送测试消息」验证。

### 如何获取钉钉 userId

通知会发送到该 userId 对应的钉钉用户（通常填你自己的）。获取方式：

- **方式一**：登录 [钉钉开放平台](https://open-dev.dingtalk.com/) → 进入扫码创建的应用 → 「权限与登录」/「通讯录管理」相关页面查看成员 userId。
- **方式二**：使用该应用的 AppKey/AppSecret 调用钉钉「获取通讯录」或「根据手机号获取 userId」接口。

> 收件人必须在企业内、且在该应用的可见范围内，否则发送会失败。

**原理**：扫码走钉钉设备码注册（`oapi.dingtalk.com/app/registration`）自动创建应用；发送使用应用机器人单聊接口（`oToMessages/batchSend`）。

## QQ / 通用桥接（手动配置）

QQ 与通用桥接通过自建的**桥接服务**中转消息（桥接服务由你自行部署，负责对接 QQ / 其他平台）。

1. **桥接发送 URL**：你的桥接服务接收消息的地址（形如 `https://your-bridge/bot/send`）。
2. **发送鉴权 Token**：桥接服务校验请求用的 Bearer Token（可选）。
3. **目标会话 ID**：桥接服务用来识别目标会话/群的标识。
4. **如需双向回复**：
   - 填写**回调验证 Token**（必填，内置 HTTP 服务据此校验入站请求）。
   - 将页面显示的「**回调地址**」配置到你的桥接服务，使其把回复转发回 TerminalBuddy。
   - 填写**允许回复的用户 ID**（只有这些用户的回复会被写入终端）。
5. 点击「保存」。

回调地址形如：`http://<电脑IP>:9600/api/bot/inbound/<通道ID>`

---

## 通用说明

- **内置 HTTP 服务**：双向回复通道（飞书、桥接）依赖内置 HTTP 服务，端口即 Web API 端口（默认 `9600`）。请确保手机/桥接服务能访问到该地址（同一局域网或公网映射）。
- **附带终端截图**：开启后飞书会在文字通知后附带终端截图。截图可能包含 Token、密钥或业务数据，请只向可信会话发送。
- **决策有效期**：超过该时间的决策消息将无法回复（绑定自动失效）。
- **将回复写入终端后发送回车**：开启后，手机回复的内容写入终端时会自动补一个回车（适用于需要直接执行的命令回复）。

---

## 故障排查

- **扫码后一直「等待扫描中」**：确认用的是对应平台的官方 App 扫码（飞书用飞书 App，钉钉用钉钉 App）；二维码过期后点「重新生成」。
- **钉钉发送失败「收件人 userId」**：userId 拼写错误，或该用户不在应用可见范围内。
- **飞书发送失败**：确认 App ID / App Secret 未被手动改动；接收目标 open_id 必须与机器人属于同一租户。
- **双向回复无响应**：检查内置 HTTP 服务是否启动、回调地址是否可达、回调验证 Token 是否一致。
