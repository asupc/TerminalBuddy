设计说明

清单输入框上方的任务卡

折叠态一行：完成数 / 总数、当前 in_progress 的 activeForm 文案、64px 进度条。展开后逐条列出，已完成打勾并淡化，进行中是高亮加呼吸点，待办是空心圈。

数据来自 TodoWrite 的全量快照：每次调用整体替换，不叠加。整轮完成后收成一行「✓ 7/7 已完成」并淡出。

代理子代理 chip 带

只列顶层代理（depth = 1），运行中的 chip 自带秒表，秒数在 chip 内部计时，不牵动整页重渲染。最多平铺 4 个，其余折叠成 +N。

执行中 · 呼吸点 + 已等待秒数
已完成 · 绿色点 + 总耗时
失败 · 红色点
已停止 · 灰色点（用户中断）

抽屉只看一个子代理

点 chip 或正文里的 Task 组头，右侧滑出抽屉，按 subagentKey 过滤出该子代理的全部消息，复用正文的 Markdown 与工具条目样式。

抽屉覆盖在消息区右侧，主列表不卸载、滚动位置不变。窄屏（< 640px）改为定位跳转，不遮挡正文。

正文Task 调用改成组头

主线程的 Task 调用原先显示成 Task\n{json} 的普通工具条目，现在渲染成紫色组头：代理名 + 派发时的 description + 状态点，点击同样打开抽屉。

来源事件与状态

task_started 建条目，task_updated 改状态，task_notification 收尾并补上耗时与工具次数；background_tasks_changed 作为完整快照做校准，快照里消失的标为已停止而不是删除。

awaited 的子代理不进「后台任务是否还在跑」的计数，但要进这里——两套口径分开写。

兼容旧会话与旧 CLI

两个字段都是可选的、为空时不序列化：旧会话 JSON、旧版 CLI（没有 task_* 事件）、从不使用 TodoWrite 的会话都不会出现空壳，界面与现在完全一致。

模拟数据用的是一个真实会话的片段。左侧所有可点元素都会响应：清单可展开、chip 可切换、抽屉可关闭，Tab 可逐项聚焦。
