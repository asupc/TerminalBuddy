坦诚盘点：为什么不能「一刀切删掉 Claude / Codex 现有直连」？
必须正视的 ACP 当前短板
1. 细粒度 Token 与缓存分项 ACP 标准 usage_update 粒度较粗（多为总上下文/总消耗），缺少目前 Claude 直连下精确的 cacheRead / cacheCreation / 缓存命中率统计。
2. 嵌套子代理抽屉（AiAgent） Claude 直连通过 --forward-subagent-text + task_* + run_id 校准实现了完整子代理抽屉；ACP 子代理扩展仍在演进，部分适配器信息不完整。
3. 结构化提问（elicitation/create）与插话（steer） 各 ACP Agent 与适配器对 elicitation/create 多选表单和运行中不打断插话 _session/steering 支持参差不齐；而目前 Claude HTTP Hook + Codex 动态工具已打磨得很稳。
4. 本地历史管理仍需 SQLite ACP session/list 只负责列举单个进程下的会话，无法替代 terminal-buddy 现有的全文检索（FTS）、星标、自定义标题、自动归档与回收站保护。
