会话页三案

现在会话页用两个标签分开「最近会话」和「服务端会话」，终端藏在快速开始的「更多」里。下面三种排版都把终端提到同一层，用「最近 / 服务端 / 终端」三个板块，分别回答：我正在做什么、这个项目做过什么、服务端此刻有什么在跑。

方案 A 松柏绿 · 深浅

静水列表

沿用现有松柏绿语言，把两个标签扩成三格胶囊，其余交给字体和留白。列表去掉厚重卡片，最近会话按「今天 / 更早」分组；服务端项目折叠成卡；终端分成「已打开」和「项目配置」两段。

  • 切换顶部三格胶囊，角标分别显示会话、项目与已打开终端的数量。
  • 最近按今天 / 更早分组；运行中的会话带底色和状态标签，未读写成「有新进展」。
  • 服务端智能体用下划线标签切换，项目折叠卡内嵌会话行，保留归属层级。
  • 终端已打开的终端横向滑动；配置行给出类型与启动按钮，原地变成已启动。
首屏：最近会话密度：中改动：小复用现有卡片

建议先上。它先解决「终端找不到」的问题，同时不打断现有视觉与组件复用。代价是三个板块仍需切换，终端比会话多一步。

方案 B 海盐蓝绿 · 弥散背景

三栏工作台

不再用标签把三个板块分开，而是把整页当成一块工作台：顶部三枚状态数字，下面三段依次铺开。最近会话是横向卡片流，服务端按项目切片，终端用深色瓦片和界面区分开。一屏能同时看到三类信息。

  • 概览三枚数字先回答「现在有什么在跑」，再往下看细节。
  • 最近横向吸附卡片，露出下一张，滑动浏览；状态直接写在卡片上。
  • 服务端智能体与项目两级切片，保留「智能体 → 项目 → 会话」的归属。
  • 终端两列深色瓦片，运行中的排在前面，配置瓦片带启动命令。
首屏：运行状态 + 最近会话密度：高改动：中新增概览

适合把服务端状态放在第一位的工作流。代价是首屏信息偏多，必须滚动才能看全三段；深色瓦片与浅色底对比强，数量要克制在四枚以内。

方案 C 纯黑 + 终端薄荷

终端视野

把会话页写成终端该有的样子：等宽字标签、点线引导、树状项目结构。最近会话像日志一样按时间列出，服务端像文件树，终端像进程表和启动命令。固定深色，强调色只留一处薄荷绿。

  • 标签等宽字加编号 [1] [2] [3]，像终端窗口的页签。
  • 最近标题与时间之间用点线引导，状态写成 [运行中] 或 [等待确认]。
  • 服务端项目按树状缩进，├─ └─ 直接表达层级。
  • 终端分「已打开」进程表与「可启动」命令，启动结果原地回显。
首屏：最近会话密度：高改动：大固定深色

适合以终端为主要入口的开发者。代价是阅读门槛与等宽中文的排版成本；如果采用，建议先在「纯黑」皮肤内做小范围验证，不必全量替换。

落地范围

三个方案共用一套数据

区别只在版式与切换方式。终端板块直接复用现有项目配置弹窗的数据与状态，不再单独维护一份。

  • AiSessionsScreen.kt三板块容器。现有 2 页 pager 扩成 3 页（A/C）；方案 B 改为同页分段与概览。
  • AiServerSessionsScreen.kt服务端板块原样迁入，保留「筛选独立于快速开始配置」的现有行为。
  • ServerProjectProfilesDialog.kt终端板块复用 projects / profiles / terminals 数据；弹窗保留给快速开始的「更多」。
  • ServerTerminalViewModel.kt提供已打开终端、启动与连接状态，三个方案共用。
  • AiNavigation.kt底部导航不变；方案 B 若采用，需要新增概览统计状态。
