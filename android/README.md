# TerminalBuddy 安卓客户端（AI 对话）

Kotlin + Jetpack Compose 原生安卓工程，连接 TerminalBuddy 内嵌 Web API，实现服务认证、原生 AI 对话与在线更新。

界面采用原生 Compose 组件与紧凑卡片布局，支持深浅色主题，使用 TerminalBuddy 的薄荷绿强调色。

## 功能范围

| 模块 | 内容 |
| --- | --- |
| 认证 | 服务地址（支持反向代理子目录）、账号、密码登录；登录成功后先校验目标服务确实提供原生 AI 接口，再保存连接。每个账号的令牌用 Android Keystore AES/GCM 加密后写入 SharedPreferences，密码不落盘；支持多个账号添加、切换、重新登录和移除，401 仅使对应账号需要重新登录 |
| 首页 | 服务连接状态、项目选择、供应商与模型选择（只列出项目已启用的 Agent）、开始对话、最近对话列表与删除；更多菜单提供账号列表，内容静默同步，异常时仅在标题显示重连提示 |
| 对话 | 输入框上方模型与用量悬浮卡片（Agent 图标、模型、思考强度、上下文进度与输入输出 token，可收展；点击查看本轮、缓存及推理明细）、原生消息列表（用户 / AI / 工具执行日志，日志默认折叠、可展开）、流式回复、逐字显示、跟随滚动与「回到最新」、多行输入、发送即显示用户消息并清空输入、待确认消息气泡左侧发送进度、发送失败恢复草稿并复用 requestId 重试、中断、Claude / Codex 悬浮决策卡片（显示在 AI 上下文上方，单选与多选均确认本项后自动继续，全部完成后提交并收起；问题支持滑动 Tab 与前后切换，未完成也可切换并保留草稿；支持自定义回答、选项说明与待处理数量）、断线重连与 REST 轮询补偿 |
| 任务通知 | 决策、工具授权、任务完成及异常结束的系统横幅通知；点击恢复对应账号与会话，登录期间持续后台监听所有账号，进程回收后定时补偿 |
| 本地缓存 | 内存 + SQLite 缓存完整会话，再次进入立即显示已有正文并后台同步；项目与模型选择、已读记录、缓存和页面状态按账号隔离，切换保留各自磁盘缓存，退出或移除仅清理对应账号缓存 |
| 布局 | 采用紧凑布局：首页为连接状态 + 新对话配置卡 + 两行最近对话列表（连续卡片、行内分割线），对话页独立为二级页并带单行导航、对话信息面板与底部操作面板 |
| 在线更新 | 「我的 → 在线更新」连接远程打包服务，免登录专用接口、选择节点、编译最新源码、实时日志、取消任务、历史产物下载和系统安装；支持后台下载与进程重建后恢复 |
| 服务端能力 | 会话保存在服务端 `AiSessions/*.json`，App 退到后台任务继续执行；重新打开回到选择首页，可从「最近对话」继续 |

Codex 主回合结束后，服务端保留同一 app-server，继续接收后台命令、子代理及自动回复。后台执行时显示“后台任务执行中”；输入框为空时可中断任务，输入“继续”或补充要求后可直接发送。新版状态需要同时更新服务端和安卓客户端；旧版客户端仍能接收后续回复并发送消息。

Claude 用户决策与桌面端复用 `AskUserQuestion` / `PreToolUse` HTTP Hook 和同一个服务端决策处理流程，手机选择回填后继续执行；原生会话按运行实例隔离投递，桌面不会弹出手机的问题。Codex 通过自身提问协议接入同一套安卓悬浮卡片。

不包含终端页面、项目文件、Git 等桌面端其它能力。

## 简版 / 完整版切换

同一个安装包内置两套一级界面，不区分包名或构建产物，可在「我的 → 界面模式」随时切换，选择保存在本机：

| 模式 | 界面 |
| --- | --- |
| 简版（默认） | 只保留快速开始单页，最近任务与历史会话平铺，无底部一级导航 |
| 完整版 | 现有客户端：底部「快速开始 / 会话 / 我的」三个一级入口 |

简版的行为：

- 移除底部「快速开始 / 会话 / 我的」切换，整页固定为快速开始。
- 新会话模块压缩留白；去掉「选择助手」文字和 Agent 名称，只保留 Agent 标志。
- 最近任务全部平铺，不再提供「查看全部」；长按仍可删除。
- 最近任务与历史会话在同一页用 Tab 切换；历史会话按当前工作项目汇总该项目全部已启用助手，不跟随新会话卡里的助手选择过滤，切换项目后自动重新读取。
- 切换工作项目后，若该项目在服务端登记了配置，会直接显示「项目配置」启动项；已打开的终端显示「继续」。
- 「我的」入口移到右上角，账号、通知、外观、在线更新等页面沿用原实现。
- 通知沿用与完整版相同的应用级监听：服务端会话完成 / 失败 / 中断、等待决策都会发送系统横幅，点击可直接进入对应会话完成决策。

首次安装默认进入简版；从「我的 → 界面模式」打开开关即可切回完整版。切换会回到首页，不影响已保存的账号、会话和终端。

## 任务通知

服务端现在把原先推送微信 / 飞书的终端任务完成与决策事件，同时写入 App 通知通道：

- **服务端任务通知**：Claude / Pi 终端完成、失败时发送结束横幅；产生等待回答或工具授权时发送决策横幅。
- **App 内决策**：点击决策通知或页面右上角的待决策悬浮按钮，打开决策面板；支持单选、多选与自定义回答，提交后由服务端回填原 Claude / Pi 决策，原微信 / 飞书通道保持不变。
- **断线补偿**：App 通过 `/ws/notifications` 订阅，重连时服务端补发仍在等待的决策；后台健康时由 REST 列表周期性补偿。
- **去重**：服务端源事件与桌面端机器人通知使用同一事件 ID，App 只提醒一次；已完成 / 已失效的决策会撤销对应通知。

首次登录后，Android 13 及以上会申请通知权限；拒绝后可在首页提示或「更多 → 通知设置」中开启。决策和任务结束分别使用高重要性的系统横幅渠道，默认开启通知声音和双次振动，并统一设置高优先级消息通知。升级时将原有普通结果渠道迁移到新版横幅渠道，保留系统可识别的用户自选重要性、禁用状态和铃声设置；决策渠道继续沿用已有设置。任一渠道被降级或关闭声音与振动时，首页和对话页显示对应设置提示。

- 首页、其他对话页和切换到其他 App 后，决策与结束事件共用同一通知发送链路，由系统弹出类似微信的顶部横幅。若只出现在通知栏，请打开首页「更多」或对话页「对话操作」中的「决策横幅通知 / 结束横幅通知」，在系统中开启对应渠道的「悬浮通知 / 横幅 / 屏幕上弹出」、声音和振动；不同手机名称可能不同，勿扰模式也可能抑制提醒。应用无法代替用户开启厂商的悬浮开关。
- 需要选择、回答问题或授权工具时发送「需要你决策」通知，处理后自动移除；任务完成、失败或中断分别发送对应结果通知。每个账号、会话及决策独立去重，初次同步不会批量通知旧的已结束任务。
- 点击通知直接进入对应对话，支持 App 冷启动和已经打开的情况。任务所属账号与当前账号不同时先恢复原账号；登录过期则引导重新登录，再继续打开原任务。任务已删除时显示提示。
- 登录后在 Activity `onResume` 启动应用级监听和前台服务，Android 14+ 使用声明了具体用途的 `specialUse`（旧系统按普通前台服务运行），不再用受六小时后台配额限制的 `dataSync`，每个已登录账号维持一条独立的 `/ws/ai` 通知连接，包含空闲和新建会话，不再依赖某个对话页面的 Socket 或曾经发现任务处于运行中。服务端约每秒检查会话版本变化，仅推送元数据，不复制或传输完整对话历史；空闲时每 10 秒发送消息心跳。通知网络队列与页面长请求分开，连续 35 秒没有收到消息帧时主动重建连接，前台服务每 5 秒检查监听任务并恢复停滞或意外退出的接收。网络切换、后台网络解除限制或退出设备休眠后立即重连；实时连接健康时 REST 每约 30 秒补偿，断线时每约 3 秒补偿，失败时逐步退避；连接不可用时仍可通过 REST 接收事件。页面退出、切换账号或保活服务启动失败不会取消存活进程中的监听。
- 常驻通知统一显示「Terminal Buddy 后台提醒」，说明它用于后台接收任务通知；正文根据任务执行、首次连接、连接恢复及后台联网受限显示具体状态。实时连接断开但摘要同步仍可用时显示「正在后台同步任务状态」，避免仍能收信时持续提示重连；启动通知也读取当前真实状态。提示只在连接或运行状态变化时更新；只有所有账号退出登录后才停止监听及保活。服务存续期间持续持有带超时与续期的 CPU 唤醒锁，使空闲时也能发现新决策和新任务；这会增加耗电，并仍需允许后台运行以获得 Doze 中的联网能力。系统重启及应用覆盖升级后尝试恢复已登录账号的接收服务。
- 服务端为任务完成、失败和中断保留 `resultRevision`，即使断线期间错过了整个运行回合，重连后的摘要也能识别并补发结束提醒；首次完整账号列表建立历史基线，不批量提醒旧结果；建立基线后，即使新会话的创建和结束都发生在断线期间，也会补发结束提醒。此链路需要同时更新服务端与安卓 App；连接旧服务端时保留 REST 同步补偿。
- 首页与对话页均提供通知权限、决策及结束横幅渠道和后台运行设置。监听期间若检测到电池优化或后台限制，会提示「允许后台」；点击后由系统确认允许后台运行。厂商的自启动、后台活动和悬浮通知开关仍需按系统设置允许。通知未获权限、渠道被关闭或发送抛错时不记为已提醒，后续同步会重试待处理的决策及结果。
- vivo / iQOO 设备提供专用后台运行指引：分别检查「电池 → 后台耗电管理 → 允许后台高耗电」、自启动/关联启动，以及最近任务锁定。自启动优先尝试 vivo 管理页面；电池设置使用公开系统入口，不可用时回退应用详情并给出手动路径。只有用户点击「我已检查」才记录已查看指引，这不代表应用已读取或确认厂商后台授权；标准电池优化豁免也不等同于厂商放行。「我的」页、对话菜单及「通知设置」均可打开该指引。
- vivo / iQOO 在本进程内连续退后台至少 90 秒后，返回前台补拉之前记录最近一次通知帧或摘要同步的间隔；若该间隔也达到 90 秒，则显示后台接收停滞提示。短暂切换不作判断；收到过状态只说明存在接收更新，不代表所有账号或任务提醒都已验证。停滞记录不直接认定为系统冻结，并写入通知诊断供真机排查。兼容处理不增加无障碍或通知读取权限，也不降低 targetSdk。
- 服务启动请求与真实运行状态分开保存，仅在系统确认 `startForeground` 成功后显示服务运行；启动失败或 10 秒内未响应时显示异常，可从「更多 → 通知设置 → 后台消息接收」重试。网络被系统限制时在常驻通知正文显示「后台联网受限」，避免将 Socket 上一次成功连接误认为当前可以后台收信。
- 「更多 → 通知设置 → 复制通知诊断」包含设备与系统版本、服务真实状态、通知权限、电池优化、后台网络限制、最近一次接收/同步时间及最近 60 条状态记录。记录跨进程重建保存，不含服务地址、账号凭据或对话正文；通知记录只表示交给 Android，并不表示系统一定已显示横幅。
- 事件基线持久化到本机，WorkManager 每 15 分钟进行补偿同步。系统回收进程或省电调度时，补偿通知可能延迟；强行停止应用后需重新打开。手机仍需能访问所连接的 TerminalBuddy 服务。当前使用本机前台服务直连，没有 FCM / 手机厂商系统推送；`specialUse`、唤醒锁、重连与 WorkManager 都无法绕过厂商强制冻结或用户强行停止，不能保证此时仍实时通知。完整分析见 [安卓后台通知分析](../docs/安卓后台通知分析.md)。

## 近期交互与缓存同步

客户端支持即时发送反馈、无感同步、完整会话缓存及多账号管理，并提供深浅主题、主题切换入口与原生 AI 长请求支持。

- 点击发送后立即在消息区显示本地用户消息并清空输入框，可以继续编辑下一条；发送进度显示在刚发送的用户消息气泡左侧，服务端确认收到后隐藏。服务端确认后合并正式消息，避免 WebSocket 与 REST 响应重复插入。失败时撤回未确认占位，仅在输入框尚未填写新内容时恢复原草稿；重试复用同一个 `requestId`。
- 会话打开时先取内存，未命中时并行恢复 SQLite 正文与请求最新快照，旧磁盘结果不能覆盖已收到的网络结果。缓存仅保存服务端确认的完整快照，按 `revision` 防止倒退，流式更新每半秒合并落盘并只更新变化的消息行；从缓存恢复时直接初始化消息展示状态，减少进入页面时的闪空和重播。
- 首页已有数据时静默同步，不显示普通刷新动画；首页和对话标题只在断线重连时显示菊花与“重连中”，每次至少展示一秒。首页不提供手动刷新按钮。
- 「更多 → 账号切换」进入账号列表，可以保存同一服务器或不同服务器的多个账号；重复登录同一地址和用户名更新原条目。新登录与切换先验证目标服务，验证期间暂停原账号同步，失败保留原连接，返回可取消。登录过期可在列表重新登录；退出保留账号条目，移除当前账号会退出登录，操作只影响本机保存的信息，不删除服务端账号和对话。升级自动迁入原有单账号和该账号的首页偏好。

## 接口（均为 TerminalBuddy 现有 Web API）

REST 使用 `Authorization: Bearer <token>`，WebSocket 使用 `?token=` 查询参数；响应直接返回 JSON 数据。

| 方法与路径 | 用途 |
| --- | --- |
| `POST /api/auth/login` | 服务账号密码认证，返回 `token`、`username` |
| `GET /api/projects` | 已登记项目与 `enabledAgents` |
| `GET /api/ai/catalog` | 可选供应商及模型（不含密钥） |
| `GET /api/ai/sessions` | 会话列表（不含消息） |
| `POST /api/ai/sessions` | 创建会话：`provider`、`providerId`、`projectPath`、`model` |
| `GET /api/ai/sessions/{id}` | 完整会话与消息 |
| `POST /api/ai/sessions/{id}/messages` | 发送消息：`text`、UUID `requestId` |
| `POST /api/ai/sessions/{id}/stop` | 中断当前回合 |
| `POST /api/ai/sessions/{id}/approvals` | 回答 Claude / Codex 确认与用户问题 |
| `DELETE /api/ai/sessions/{id}` | 删除空闲会话 |
| `/ws/ai/{id}?token=...` | 首帧完整会话，后续推送元数据与变化的消息 |
| `/ws/ai?token=...` | 独立后台通知连接：全部会话元数据、版本变化及空闲心跳 |

服务端实现见仓库 `docs/原生AI会话API.md`。

## AI 正文 Markdown

AI 助手正文使用原生 Compose Markdown 渲染，支持标题、粗体、斜体、删除线、有序及无序列表、引用、分隔线、链接、行内代码、多行代码与 GFM 表格。代码块和宽表格可横向滚动；长按仍可选择和复制文本。用户输入及工具执行记录保留原文。图片首版显示可点击链接，公式与 Mermaid 不在本轮范围。

每条消息保留自己的解析快照。解析在后台进行，流式阶段合并高频更新；新结果就绪前保留旧内容，输出结束后接收完整解析结果。相同正文不因工具记录、用量或连接状态更新而重新解析；列表项离屏再进入时复用已知结果。解析失败回退到原文，取消任务不覆盖旧结果。Markdown 解析状态不参与“思考中”显示判断。

客户端固定使用 `com.mikepenz:multiplatform-markdown-renderer-m3:0.38.0`，关闭文字尺寸补间，沿用现有消息列表的自动滚动。链接仅打开 HTTP/HTTPS；TB 的正文、链接、代码和表格随深浅主题切换。

## Ai 模型与用量悬浮卡片

Ai 二级对话页在原有输入框上方显示独立悬浮卡片，采用薄荷绿强调色、圆角细边框，随应用深浅主题切换。顶部标题栏仅显示单行对话标题；卡片首行依次展示“图标 + Codex / Claude + 模型 + 思考强度”，长模型名以省略号显示，右侧箭头可收起整张卡片；收起后不占布局高度，改为消息区右下角的浅色悬浮展开按钮。输入框保留原有外观、多行输入和发送 / 中断按钮。点击卡片首行，或从“对话操作 → 上下文与 Token”进入详情，可查看模型、思考强度、已用 / 容量、本轮用量、会话累计、缓存读写和推理输出明细。

- 模型和思考强度按当前会话的供应商标识、模型标识匹配服务端模型目录。思考强度显示中文等级；未提供时显示“跟随服务端”。
- 用量来自 TerminalBuddy 会话的 `usage`，复用原有 REST / WebSocket 实时同步；手机退到后台后服务端继续统计，重连恢复最新快照。
- 当前上下文与会话累计分别显示。Claude 上下文采用最近调用的输入量，包含缓存读取和写入；Codex 的上下文估算及配置容量使用 `≈` 标注。
- 缓存和推理明细是输入、输出的组成部分，不再重复相加；累计消耗可以超过上下文容量。
- 卡片刷新时保留本会话上次已知数值和上下文进度，新统计到达后直接替换；上下文进度条只在拿到大于 0 的有效进度时前进，缺失、刷新中或计算结果为 0 都沿用上一次进度，不会归零后回弹；已用量拿到过正值后，0 也视为统计缺失而不再覆盖已知值（新会话首次的 0 仍照常显示），避免出现 `0K/950K` 再跳回真实数值；总上下文的容量同样只认大于 0 的新值，缺失或 0 都沿用上一次已知容量，不会短暂回退成 `—K`；从未拿到有效比例时不绘制进度条，只显示「上下文 `已用/容量`」文字，占用率显示 `—` 而非误报 `0%`；首次无数据时使用 `—K`，压缩后的等待状态在详情中说明。旧会话和中断后的部分统计会明确标注，旧版本服务端没有 `usage` 时仍可正常聊天。

相关代码为 `data/AiModels.kt`、`ui/AiUsageBar.kt`、`ui/AiConversationUsageCard.kt` 和 `ui/AiConversationScreen.kt`，接口口径见仓库 `docs/原生AI会话API.md`。

## 使用前提

1. 服务端为包含原生 AI 会话接口的版本（桌面端或独立服务器模式均可）。
2. 在 TerminalBuddy 开启 Web API，设置账号密码，并登记手机需要使用的项目目录。
3. 服务运行账户下已安装并登录 Claude Code / Codex CLI，供应商与模型在服务端配置；手机不保存模型 API Key。
4. 手机与服务端网络互通。模拟器访问本机服务用 `http://10.0.2.2:9600`；手机里的 `127.0.0.1` 指向手机自身。

## 在线更新与远程打包

在「我的 → 在线更新」只填写更新服务地址即可进入，无需登录打包服务或提供后台令牌。推荐分享完整接口地址 `http://taihe.678120.cn:8086/api/public/terminalbuddy/android`；填写主服务地址也会自动连接同一个专用接口。旧版以 `/api/terminalbuddy/android` 或 `/api/android` 结尾的地址仍可输入，客户端会提取主服务地址并改走免登录接口，不回退使用管理员认证。

此版本需要先更新远程打包服务，再安装新版 TerminalBuddy App，构建节点和 FRP 配置沿用现有设置。升级时迁移旧更新服务地址，并删除在线更新功能曾保存的旧版登录令牌；终端账号使用独立存储。成功连接后，下次打开直接进入工作台；右上角服务按钮可更换地址。

当前部署地址：

| 网络 | 填写地址 |
| --- | --- |

远程打包服务提供 `/api/public/terminalbuddy/android`，只开放 TerminalBuddy 的状态、节点列表、构建、历史、增量日志和项目专属下载票据；旧的管理员接口继续要求登录，不会向共享用户签发后台令牌。共享用户只能取消本设备发起的任务，管理员任务和其他设备的任务不能取消；客户端按服务地址自动保存随机设备标识，服务端只保存其摘要，不在公开历史中返回该标识或真实管理员账号。公开编译入口全局保留 30 秒提交间隔，沿用服务端统一的构建任务互斥。可通过后端环境变量 `TERMINALBUDDY_PUBLIC_ENABLED=false` 关闭免登录入口。打包节点主动连接主服务，不需要映射 Debian 打包节点端口。任务、版本号、签名和安装包与管理端的「TerminalBuddy App 打包」共用同一份数据。

点击「编译 APK」时，服务端先更新所选节点的代码，再按已有独立版本计数编译并签名。构建期间可取消本设备发起的任务；日志支持自动跟随、复制和下载，右上角可查看历史任务和完整详情。离开页面不会停止服务端构建。下载由系统 DownloadManager 在后台执行，状态持久化，重新进入可继续查看。APK 下载完成后检查服务端 SHA-256（提供时）、包名、版本与当前安装签名，点击「安装」交给系统安装器；首次需允许 TerminalBuddy 安装应用。保留项目原 Release 签名，覆盖安装后保留应用数据。

部署新版远程打包服务后，由管理员在管理端的「TerminalBuddy App 打包」编译并安装新版 TerminalBuddy，再将 APK 和上述独立接口地址分享给其他用户；其他用户无需登录打包服务即可在 TerminalBuddy 内完成更新。

## 构建

```bash
cd android
# 需要 JDK 17+ 与 Android SDK 36；local.properties 中配置 sdk.dir
./gradlew :app:assembleDebug        # 调试包
./gradlew :app:testDebugUnitTest    # 单元测试（地址处理、模型解析、请求体约束）
./gradlew :app:assembleRelease      # Release（未配签名时为 unsigned）
```

一键构建：在仓库根目录执行 `./xcj/build-android.sh`，脚本在本机直接使用 JDK 17 + Android SDK 36 构建（首次自动下载 SDK 到 `~/.android-sdk`，无需 Docker），产出 `dist/TerminalBuddy_<版本>_android.apk`（Release 已签名）。简版与完整版是同一 APK 内的运行模式，不需要分别构建。

在 Android Studio 中直接打开 `android/` 目录即可。

仓库 `scripts/` 目录提供一键构建、安装与启动脚本：

```bat
scripts\build-android.bat            :: 自动找 JDK/SDK → 编译已签名的 Release APK → 安装 → 启动
scripts\build-android.bat <序列号>   :: 多台设备时指定目标
```

产物位于 `android/app/build/outputs/apk/release/app-release.apk`，使用项目现有 Release 签名。

脚本走 `scripts/build-android.ps1`：优先 `JAVA_HOME` 与 `android/local.properties` 的 `sdk.dir`，其次 Android Studio 自带 JDK 和 `ANDROID_HOME`；单台设备自动选择，多台提示输入序号。设置 `TERMINAL_BUDDY_NO_PAUSE=1` 可跳过结束时的等待按键。
